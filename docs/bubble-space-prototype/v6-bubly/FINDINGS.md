## 1. ひとこと結論

**バブリの画面は、1文字も変えずに載った。**

`CsvObjectListView.tsx` と `CsvObjectDetailView.tsx` は**リポジトリの本物をそのまま import** している
（写しでも作り直しでもない）。変えたのは `import ... from "@bublys-org/bubbles-ui"` の**行き先だけ**で、
それも esbuild の `alias` で差し替えている ── **ファイルの編集は 0 行**。

そして **masa さんが「残したい」と言っていた見え方が、規則の上で出た**：

```
一覧だけ         一覧 倍率 0.982
詳細を開いた後   一覧 倍率 0.773   詳細 倍率 0.986（右・手前）
```

> 「リストは奥に行き（＝小さくなり）詳細が前面に来る、という形になっていた。
>  それにより、画面の横幅を節約して、より多くの情報を表示できる」

特別扱いは足していない。**開いたら X のレンズを魚眼にする**、それだけ。

## 3. ぶつかった（3つ。全部その場で直した）

### ① `setPointerCapture` が、泡の中のクリックを全部食べていた ★ いちばん大きい

**症状。** 一覧の項目をダブルクリックしても、詳細が開かない。膜は出るのに。

**なぜ。** 押した瞬間に層が `setPointerCapture` していた。
ポインタを捕まえると、**そのあとの `click` / `dblclick` まで捕まえた要素へ配られる**。
ラボは中身が飾りだったので踏まなかった。

**直し方。** **掴むと決まってから捕まえる**（`useBubbleInput` の `capture()`）。
あわせて「本文（空間ではない中身）を押したら何も始めない」を足した
── それは中身のものなので、泡の側は手を出さない。

**規則は増えていない。** ③ が既に「中身の箱はその泡のものではない」と言っている。
`inContent` が見ていたのは「空間を持つ泡」だけだったのを、「**本文を持つ泡**」にも広げた
（`hasContent`）。既存 `bubbles-ui` も「ヘッダで掴む」なので、向きもそろっている。

### ② 開いた隣どうしが、少しドラッグしただけで「くっつい」て並びになった

**症状。** 詳細を少し動かして離すと、一覧と詳細が**見えない親に入って並びになり**、
同じ倍率（0.884）・同じ高さに揃って、「詳細が手前」が消えた。

**なぜ。** 僕が決めた「隣に開くときの隙間」が **24px**、
くっつく距離（`METRICS.SNAP_EDGE`）も **24px**。同じだった。
開いた直後の2つが、いつも「くっつく一歩手前」にいたことになる。

**直し方。** 隙間を `SNAP_EDGE × 2` にした。画面での隙間は倍率でさらに縮むので、2倍とる。

★ **これは規則どうしのぶつかりではなく、僕が置いた定数のぶつかり。**
ただし「開く位置は、くっつく距離より広くなければならない」は、
今後どんな開き方を足すときにも効く条件なので書き残しておく。

### ③ 題名が二重に出た

**症状。** 泡の枠に「夜勤の引き継ぎ表」、中身の `<h3>` にも「夜勤の引き継ぎ表」。

**なぜ。** 僕が枠に**題名**を出していた。
**現行 `bubbles-ui` の泡は、枠に url（パンくず）を出している**（`BubbleView.tsx` の `e-styled-url`）。
中身が自分の題名を出すので、枠は「いまどこにいるか」を出す ── そちらが正しかった。

**直し方。** 枠を url のパンくずにした。domain の `title` は残す（掴んだときの札・一覧に要る）。

## 4. 踏まなかった（けれど、まだそこにある）

- **「ホスト自身の本文の席」**（未決）── この画面は「中身を持つ泡」ではあっても
  「**中身を持ちながら、子の泡も入れている泡**」ではなかったので、踏まずに済んだ。
  勤務表のように「表があって、その中から泡が開く」画面をやると踏む。
- **世界線**（`useCasScope` / `WorldLineFeature`）── feature 層を省いたので通っていない。
  カメラをノードに紐づける枝（DECISIONS.md）は、まだコードになっていない。
- **Redux** ── `BubbleSpace` は世界を外から渡せる口（`world` / `onChange`）を開けてあるだけ。
  どこに載せるかは決めていない。
- **補間（CSS transition）** ── 決めてはあるが、まだ書いていない。開くと泡がぱっと出る。

## 5. 置き換えに要る口は、4つだけだった

バブリ6つを数えた（`ObjectView` `BubbleRoute` `openBubble` `BublyApp` 系）:

```
ObjectView   223     ← 本丸
BubbleRoute   65     どのオブジェクトにどの画面を出すか
openBubble    37     開く
BublyApp 系   36     外枠（Provider・メニュー）
```

`bubble-layout-feature` はこの4つに当てて作った。**`openingPosition` だけは落とした**
（どこに置くかは親の View が決める ── DECISIONS.md）。
ただし移行のため、`ObjectView` は `openingPosition` を**受け取って無視する**。
これがあるので、バブリの画面を編集せずに載せ替えられる。
