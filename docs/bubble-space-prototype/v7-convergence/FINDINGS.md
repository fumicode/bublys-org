## 1. ひとこと結論

**旧の `process.layers` は、新しい規則の言葉で言うと「Z を詰める」だった。**
旧の文型（開く・並べる・閉じる）は、規則を1つも足さずに Z 軸で書ける。いまの feature 層が使っている
X の魚眼は、**開く枚数が増えると関心の順を逆転させる**（詳細 0.755 ＜ 一覧 0.773）。

### なぜ魚眼だと逆転するか

規則①「泡の像は、泡の端をレンズに通した間」。だから **魚眼は幅に罰を与える**。
続けて開いた同種は見えない親（並び）に入り、並びは1つの泡として像を作る。
2枚で 600px → 0.912、3枚で 900px → 0.755。**開けば開くほど、いちばん見たいものが小さくなる。**
CARRYOVER.md が既に「魚眼は2枚専用だった」と測っていたのと同じ根。

## 3. 収束の芯 ── 旧の layers ＝ Z を詰める

```
旧   process.layers = [ [d1,d2,d3], [list, groups] ]     配列の何番目にいるか ＝ 奥行き
                          0段           1段               （泡は奥行きの値を持っていない）

新   泡が値を持つ      d1.z=-1  d2.z=-1  d3.z=-1      list.z=0  groups.z=0
     View が読む       Z ＝ 自由Z · 詰める · 透視
                       値ごとに帯 →   帯0 = {-1}        帯1 = {0}
                       位置 ＝ 帯の番号 × step          0          0.4274
                       透視 m = 1/(1+0.26·dz)           1.00       0.90
```

| 旧の動詞 | 新しい規則での言い方 | 書く値 |
|---|---|---|
| `popChild`（別の種類を開く） | いちばん手前より小さい Z を持たせる | 新しい泡の `free.z` だけ |
| `joinSibling`（同じ種類を開く） | 兄弟と同じ Z を持たせ、並びに加える（③） | 新しい泡の `free.z` と並び |
| 閉じる | 消す | — |
| 空のレイヤーが詰まる | **帯は値ごとに作るので、空の帯は最初から無い**（④） | — |
| `layers.unshift` で全員が1段下がる | 帯の番号が1つずつ増える | **他の泡の値は1つも書かない** |
| 測る → Redux → 再レンダ → 置く | 解いた答えから純関数で置く（`screenToAxis`） | — |

### A 案と B 案（`run.mjs` が両方走らせる）

| | A：いまの規則のまま | B：`arrange.ts` の1語を変える |
|---|---|---|
| Z の View | 自由Z · **そのまま** · 透視（外の空間の既定そのもの） | 自由Z · **詰める**(step 0.4274) · 透視 |
| 開く | 1段手前の値を書き、**Z の焦点をそこへ送る** | 小さい値を書く**だけ** |
| 閉じる | 焦点の面が空になったら、焦点を次の面へ送る | 消す**だけ** |
| 焦点を書く回数 | 開く・閉じるのたび | **0 回**（実測：最初から最後まで 焦点z = 0） |
| 真ん中の面だけ空にする | ★ 詰まらない（一覧 0.818 のまま） | **詰まる**（一覧 0.900） |
| 要る変更 | なし | `values.indexOf(v)` → `values.indexOf(v) * A.step`（`arrange.ts:86`・`lab.html:627`） |

B の1語の中身：**いま Z の「詰める」は帯の幅が 1 に固定**（だから CARRYOVER が「Z の詰めるは必ず 0.7937」
「空の段が詰む と 1段 0.90 が両立しない」を“出せなかったもの”に入れていた）。
X・Y の詰めるは帯の幅を泡の大きさから取るが、**泡は Z に厚みを持たない**。だから帯の幅は View の `step` が持つ、が筋。
Z に詰めるを当てている場面・検査・プリセットは **0 件**（grep）なので、既存の20本・101本には響かない。

**ブランチに入れてあるのは A**（domain を1文字も触らずに試せるから）。B は規則の側の変更なので入れていない。

## 5. ついでに見つけたもの

### ① 閉じると、触っていない兄弟が動いていた（直した）

並びの中の詳細（300px）を1つ閉じると、残りが **150px** 右へ動いた。旧は動かない。
`reshape` は「泡が**出ていって**縮んだ並び」の先頭を⑤で留めるが、見つけ方が「親が変わった泡」からなので、
**消えた泡は数に入らない**（ラボには泡を消す口が無かったので、誰も踏んでいなかった）。
feature の `closeBubble` で、縮む並びの先頭を `keep` に渡した。実測 **0.00px**。
★ 本来の置き場は domain の `reshape`（消えた泡の元の空間も「縮んだ」に数える）。domain は触っていない。

### ② 視点を送ると、接していた縁が重なる（視差）

3枚目で視点を X に送ると、奥の一覧（m=0.9）は手前より動きが小さいので、縁が **34px** 重なる。
透視のカメラとしては正しい。CARRYOVER のときの masa さんの言葉
（「A の右端が、より手前の B の左側によって隠されても構わない場合もある」）の範囲に入ると見ているが、**見てほしい**。

### ③ `apps/bublys-os` の `/bubble-ui` が落ちる

`useCas must be used within a CasProvider`。本物の入口は `/`（`[[...slug]]`）で、`/bubble-ui/page.tsx` は
`DomainRegistryProvider` を持たない古い頁。今回の変更とは無関係（変更 0 行の時点で落ちていた）。

### ④ v6 のデモは、ライブラリの `dist` を掴む

`nx test bubble-layout-feature` は依存（layout・ui）しかビルドしない。feature を直したら
`npx nx build bubble-layout-feature` してから `build.mjs`。一度これで古い絵を見て数字が合わなかった。

## 6. masa さんに決めてほしいこと

### 決めどころ1：横に開いたときの奥行きを、魚眼で付けるか、面で付けるか

魚眼は masa さんの提案（`openAt.ts` 冒頭の引用）で、狙いは「ただ兄弟にすると同じ大きさになって、旧の良さが損なわれる」を
避けることだった。**狙いは面でも満たせる。** ちがいは実測のとおり：

| | 魚眼 | 面 |
|---|---|---|
| 2枚 | きれい（0.773 ／ 0.986） | 0.900 ／ 1.000 |
| 3枚より先 | 見たいものが縮む・順が逆転 | 全員 1.000 |
| 横幅 | 潰して収める | 潰さない。溢れたら視点を送る（奥は少し隠れる） |
| 開いた瞬間 | 視点が X に寄る（画面が動く） | 奥行きだけが変わる |

魚眼を捨てる話ではない。**魚眼は View の1つとして残る**（coverflow・世界線）。決めるのは「開く」の既定だけ。

### 決めどころ2：Z の「詰める」の帯の幅を `step` にするか（B 案の1語）

入れれば、`settlePlaneAfterClose` も、開くときの焦点の書き込みも**要らなくなる**
（CLAUDE.md の「シンプルなルールで自然な動作」── 面は値から出て、焦点は誰も触らない）。
ラボ（`lab.html:627`）にも同じ1語を入れて「差 0」を保つことになる。

### 決めどころ3：縁を接して開くと、少しドラッグしただけで「並び」になる ★ 旧の良さと、新しい仕組みの正面衝突

実測（`snap-conflict.mjs`）：開いた直後の詳細のヘッダを **(6, 4)px** ドラッグして離すと、一覧と見えない親に入る。

```
開いた直後     一覧 x554 0.900    詳細 x860 1.000          ← 縁が接している
6px ドラッグして離す  (並び) x554        詳細 x894 1.000          ← 34px の穴。以後、並びの中に閉じこめられる
```

- 良い知らせ：並びの中でも**奥行きは保たれる**（0.900 ／ 1.000）。Z は見えない親を素通しする（③）
- 悪い知らせ：詰めるは自前の幅 340 で席を取るのに、描かれるのは 0.9 倍の 306。だから穴があく
- v6 は同じ形を「開く隙間はくっつく距離（24px）より広く」で避けた。**接して開くなら、その手は使えない**

| | |
|---|---|
| あ：**くっつくのは、同じ面の泡どうしだけ** | `snapCandidateAt` に1行。旧の「兄弟＝同じレイヤー」と同じ線引き。規則③に1文足すことになる |
| い：接するのをやめ、48px あけて開く | いまの魚眼と同じ。旧の「2つで1つに見える」は手放す |
| う：そのまま | 面がちがう泡の並びを認める。穴（34px）をどうするかが次に来る |

### 決めどころ4：奥の泡を触ったとき、Z の焦点も寄せるか

旧は「描く順だけ上がる。倍率も位置も変わらず、**何も消えない**」（実測 z 98→100）。
いまの規則②は X・Y・Z ぜんぶの焦点を送るので、面で奥の一覧のヘッダを触ると、**手前の詳細が消える**。実測：

```
詳細を開いた            一覧 0.900            詳細 1.000
一覧のヘッダを触った    一覧 1.000            詳細 1.125・display:none   ← 焦点より手前（dz<0）
```

DECISIONS.md のとおり縁のスタックに積まれる想定だが、**スタックはまだ feature に無い**ので、いまはホイールでしか戻れない。
本文を触っても何も始まらない（v6 で決めた）ので、**一覧の項目をダブルクリックして次を開く流れは無事**。効くのはヘッダを触ったときだけ。
