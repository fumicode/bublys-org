# 旧 bubble-ui の良さは、5つの規則の上に残せるか

## 1. ひとこと結論

**残せる。ただし masa さんの見立て（横に開く＝見えない親＋X魚眼）はそのままでは出ない。**
**見えない親に魚眼は刺さらない（6担当が独立に測って 倍率差 0.0000）。「リストが奥へ行って小さくなる」の直訳は X魚眼 ではなく Z（透視）で、そちらは見えない親の中まで効く（1.0000 / 0.9058）。**
**masa さんの新しい一言（右端が隠れてもいい）で、いちばん良い絵が変わった ── 潰す魚眼ではなく、隠す「等間隔×平行」＋ Z の段。**

## 3. 「書ける」もの ── View の中身と、masa さんの手本の答え合わせ

### ★ masa さんの手本は、字義どおりには出なかった

**見えない親（③）に X魚眼 は刺さらない。**6担当が別々に測って全部同じ。

| 担当 | 見えない親の中の倍率 | 差 |
|---|---|---|
| interest-depth | 付箋A / 付箋B | **0.0000** |
| narrow-screen | fA 0.990 / fB 0.990 | **0** |
| open-where | 0.9823 / 0.9823 | **0.000000** |
| where-from | 0.9812 / 0.9812 / 0.9812 | **0** |
| where-am-i | 0.9587 / 0.9587 / 0.9587 | **0.0000** |
| undo-time | View が 順序·詰める·平行 のまま変わらず | — |

理由はコードに書いてある：`lab.html:554  spaceId = windowOf(spaceId);  // ③ 見えない親は View を選べない`。
並びの View は `lab.html:414` で `lens:"parallel"` 固定。setAxis は外の窓へ回り、**root の X が魚眼になる**。

### ★ ただし「見立ての半分」は当たっていた ── 相手が魚眼ではなく Z

**Z（透視）は見えない親の中まで効く。**③ が「Z は軸まるごと外の窓のもの」だから。

- 見えない親の中で **1.0000 / 0.9058**（差 9.42%）── where-from 検証
- 見えない親＋Z（順序·透視）で **fA 0.8953 / fB 0.8104 / fC 1.0000** ── open-where 検証
- 並びの中で **giji 1.000 / kinmu 0.906** ── narrow-screen 検証

そして出てくる数が、現行 bubble-ui のレイヤー倍率とほぼ同じ：

| | 段0 | 段1 | 段2 | 段3 |
|---|---|---|---|---|
| 現行 bubble-ui（1−0.1n） | 1.00 | 0.90 | 0.80 | 0.70 |
| Z＝順序·等間隔(0.4274)·透視 | 1.0000 | **0.9000** | 0.8182 | 0.7500 |

合うのは一段目まで（透視は寝ていく）。6段まで伸ばすと 0.6923/0.6428 対 現行 0.60/0.50。

### ★ X魚眼 そのものは、masa さんの線（潰れて読めない＝駄目）を自分で越える

魚眼は **2枚専用**だった。報告はぜんぶ2枚で測っていた。

| 枚数 | いちばん奥の倍率 | 「佐藤」の字 |
|---|---|---|
| 2枚 | 0.768 | 16.9px |
| 3枚 | 0.368 | 8.1px |
| 4枚 | 0.144 | **3.2px** |
| 6枚（窓3000pxでも） | 0.389 | 8.6px |

同じことが別の担当でも出た ── root の泡10個に魚眼をかけると **題名が消えた泡 6/10**、最小 倍率 0.0118（幅 1.53px）。undo-time では 一覧 倍率 **0.441**・字 5.3px（現行 bubble-ui 自身が「読めない」と決めた 0.8 を大きく割る）。

**2枚だけなら魚眼はきれい**：リスト 260→182.6px（0.7022・字 15.4px）／詳細 420→402.6px（0.9585）／継ぎ目 12.2px。しかも**幅を振っても継ぎ目 12.2px で一定**（負の隙間は 100px あたり 10px ぶれる）。

### ★ masa さんの新しい一言で、いちばん良い絵が変わった

「右端が隠れてもいい」なら、**潰す魚眼ではなく、隠す 等間隔×平行**。4担当が別々に同じ所に着いた。

| 組み方 | 箱・横幅 | いちばん奥の倍率 | 読めない泡 |
|---|---|---|---|
| 順序·詰める·平行（ただ兄弟） | 742px | 1.000 | 0/7 |
| 順序·等間隔·**魚眼**（coverflow） | 340px | 0.313（字 3.75px） | **2/7** |
| 順序·**等間隔(30)·平行** | **340px** | **1.000** | **0/7** |
| 順序·等間隔(40)·平行 | 358px（52%節約） | 1.000 | 0/7 |

- 別担当：X 等間隔(step −110)·平行 ＋ Z 順序·等間隔(0.15)·透視 → 総横幅 2788→**1364px**、倍率の帯 0.762〜1.000、**題名が消えた泡 0/10**
- 別担当：等間隔 step=260 → リスト 0.8730（字 10.5px）・右端の **50%** が詳細の裏、空いた幅 1297.6px
- 別担当：等間隔 step=190 → 820→**600px**（220px 空く）・倍率 1.000・字 12.0px・一覧の右 **73%** が隠れる
- 別担当：等間隔 step=240 → 隠れ 150.0px・リスト 0.888（題名 10.7px）。隠れた帯を左から突くと 112px まで議事録に当たる＝**掴める**

**step ひとつが「隠す量」と「読める大きさ」を同時に回すつまみ。** 140→隠れ 249px・0.949／240→150px・0.890／340→54px・0.804／440→0px・0.705。

切り抜きではない（RULES:126）。**重なりを作るのはレンズではなく並べ方**（RULES.md:93）── 規則が自分でそう書いている。

## 4. 「ぶつかる」もの ── masa さんが選ぶところ（8つ）

### 決めどころ1（いちばん大きい）：`order` は1つしか無い

3担当が別々に踏んだ。X に順序（＝横に並べる／見えない親）を刺すと、Z にも順序は刺せない。両方刺して詳細を触ると、**手前に来ると同時に並びの左端へ飛ぶ**。

- kinmu x 956.8 → **−674.0**
- fC x 767.43 → 660.00、触っていない fA が **85.94px** 動く
- coverflow が cf0..cf6 → cf3 cf0 cf1 cf2 cf4 cf5 cf6 に崩れる

| | 甲：横に並べるを取る | 乙：触ると手前を取る |
|---|---|---|
| X | 順序（③ の並び／横に並べる） | 自由X |
| Z | 自由Z ＋ アプリが「1段下げる」を書く | 順序·等間隔(0.4274)·透視 |
| 得 | くっつく・まとめて掴める・並びの中でも大小は付く（1.000/0.906） | アプリは何も書かない。②だけで入れ替わる。現行のレイヤーと同じ式 |
| 値段 | ②「触ると手前」が使えない | 「A の右に開く」は座標を書くことになる |

※ もう1つの道（規則が増える）：**「手前へ」を Z 専用の順序に書く**。RULES「泡が持つもの」に1行増えるが、並びと奥行きが独立になる。**増やす提案は masa さんの判断**なので、道があることだけ置く。

### 決めどころ2：開く先を「並べ方」で決めるか「座標」で決めるか

| | あ：並べ方（③ or ④ gap=0） | い：座標（X＝自由X·そのまま） |
|---|---|---|
| 縁 | 接する **0.000px** | 接しない |
| ⑤ | **破れる**。泡が1枚増えると触っていない泡が全部 **160.00px**、角をドラッグするだけで 71.5px | **完全に守られる 0.000px**（開いても角をドラッグしても） |
| 継ぎ目 | 枚数が増えると荒れる（−25.3 / 9.9 / 76.9px） | **14.00px ぴったり**（4枚・横幅 936px・いちばん奥 0.562 で字 12.4px） |
| いまの実装 | — | **現行 bubbles-ui はこちら**（SmartRect.ts:140 `toLayerBelow().toGlobal().getNeighbor()`） |

→ 「い」を選ぶことは “ui に逃げる” ではなく **“いまのやり方を続ける”**。

### 決めどころ3：奥行きを倍率で見せるか、描く順だけで見せるか

| | あ：Z に 透視 | い：Z に 平行（flat） |
|---|---|---|
| 触った泡 | 手前へ来て**大きくなる** | 手前へ来る（z-index 1→32）が大きさは変わらない |
| 掴んだ点 | 押しただけで **123.57px** 逃げる（pin の行き先を「掴んだ点」にすれば 0.00px） | **0.00px** |
| 触っていない泡 | **52.75px 動き 幅 −9.4%**（pin 3通り試して全部残る） | **0.00px** |
| 横幅 | 節約できる | 節約できない |

※ 間隔を下げても逃げは消えない（0.05 でも 24.46px／7.19px）。0 になるのは奥行きが無いときだけ。

### 決めどころ4：視点をどこで止めるか

いまの止め方は「中身が箱に収まるまで」。動ける量は **(画面幅 − 中身の総幅) ÷ 2**（実測：総幅1180 → 130.00px ちょうど、総幅2530 → 0.00px）。自由軸には止め方が無く、背景20回で **画面に見えている泡 0/58**。

- **A：いまのまま** ── 中身が画面より広くなった瞬間、視点が釘付け。自由軸では迷子になる
- **B：「泡が置いてある所まで」に付け替える** ── 全部の並べ方・全部のレンズに効く。**規則を1つも増やさない**（RULES.md に焦点の止め方は無い）。現行 bubble-ui は既にこちら（bubbles-slice.ts:845「何もない void に scroll してバブルを見失う事態を防ぐ」）

### 決めどころ5：ホスト自身の本文に、④ の帯の中で席を作るか

議事録（自前 300×310）に付箋Cを落として箱は **Δ0×0**。ラボは `.bub.host .bd{display:none}`（lab.html:95）で本文を消して、この問いを踏まずに来た。
**A：本文にも席を1つ作る**（④ の帯に値を持たない席が1つ混じる）／**B：ホストになった泡は本文を捨てる**（中身のある泡に放り込めなくなる）。

### 決めどころ6：「開く」をどこに置くか

② の表に「開く」が無い。v5 で中へ入る道は掴んで落とすだけ（dblclick は v3/v4/v5-dom とライブラリのどこにも無い）。
**A：② に1行足す**（軸なしの行は既にある）／**B：掴んで落とすだけにする**／**C：ui だけの寄せ（視点）として復活**（README §6-A が自分で挙げている。domain を触らない）。
見積り：**onDoubleClick 41箇所／19ファイル**、ObjectView は **82ファイル**。
※ ①〜⑤ に「泡を作る」も「消す」も無い。**「開く＝物の泡を作って置く」は、いま既に規則の外。**

### 決めどころ7：焦点（＝時間の中の現在地）を世界線に載せるか

焦点は泡の持ちもの（BubbleState.focus）なので world に必ず入る。履歴の空間で16歩ぶんドラッグすると、泡の値は 0個 変わらないのに world は **16回** 変わる。
さらに世代が1つ増えると ④「塊の中央を空間の中心に」で **触っていない泡が 27.80px 動く**（本物の WorldLinesCanvasView は 0px）。⑤ を守るなら ui が commit のたびに焦点を入れ直す ＝ **泡を1つも触っていない commit でも焦点の数が変わる**。
**A：載せない**（commit 前に落とす。現行の projectArrangement と同じ形）／**B：載せる**（視点も巻き戻る。ノードが増える）。

### 決めどころ8：泡に「中身が何か」を持たせるか

泡の鍵は13個で url に当たるものが無い。題を全部入れ替えても配置の差は **0** ＝「同じ場所で中身が変わる」の構造のほうは既に出ている。
**A：url を1つ足す**（title/hue と同じ「配置が読まない持ちもの」。規則の式は変わらない）／**B：泡は id だけ**（対応は ui 側）。

## 5. 「落とす」もの ── 規則が問題ごと消した

| 落とすもの | なぜ要らなくなったか |
|---|---|
| ヘッダのクリップ（窓の外に出ると掴めない） | 「切り抜きはしない」（RULES:126）。はみ出し 20.1px でも hitAt は本人を返す |
