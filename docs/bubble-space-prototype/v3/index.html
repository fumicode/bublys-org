bubble-lab v3 —— 泡の見え方は、親の View で決まる

7つの単体プロトタイプ。1案 = 1ファイル、カードをクリックすると開く。 語彙と約束は SPEC.md。

いまのルール — 5つ

①〜④ は「値 → 見え」を決める。⑤ だけが逆で、「さっきの見え → 値」を書き直す。

①

公理 値 → 見え 00 で見る

泡の見え方は、その泡を入れている親の View で決まる。View は軸（X・Y・Z）ごとに 次元・並べ方・レンズ を持つ。これが入れ子ごとに繰り返される。

②

操作は軸に従う 値 → 見え 04 で見る

泡を掴んで横・縦に引くと、その軸の次元が 書けるなら書く（動く・並べ替わる・マスを移る）／ 書けないなら視点が動く／なしなら何も起きない。ホイールは奥行きの視点。 触った泡は手前へ——Z 軸に書けるならそこへ書く（「最前面」になるのは Z が順序のときだけ。 自由座標では焦点の面まで）。

③

見えない親は体を持たない 値 → 見え 01 で見る

「A の左に B がスナップ」＝「見えない親が中身を左右に並べている」。隣り合う関係は持たない。 その見えない親は箱も、奥行きも、View も、自分のものは何ひとつ持たない。持っているのは並べ方ひとつだけ。 空間の出入りも、外へたどった窓で数える。

④

並べる＝帯の式 値 → 見え 03 で見る

値ごとに帯を作り、帯の中に揃えて置き、塊の中央を空間の中心に。 詰める＝帯の幅はその値の泡の最大、等間隔＝帯の幅は間隔。違うのは帯の決め方だけ。 重ならないことを保証するのは詰めるだけ。泡はその端をレンズに通した像の幅で縮むので、 重なりを作るのはレンズではなく並べ方。

⑤

触っていない泡は、画面の上で動かない 見え → 値（逆） 05 で見る

泡の位置は箱の中心。だから中身が変わって箱が伸び縮みしたら、触っていない泡の 見えている場所を保つように、位置を書き直す。別の仕組みではなく、 「位置＝中心」を選んだことから必然的に出てくる補正（切ると、伸びのちょうど半分だけ動く）。

7つの案

絵をクリックするとプロトタイプが開く。緑の点＝分かったこと、赤の枠＝直せなかったこと。

00

親の View だけで並べる（土台）

6つの場面（メモ／横に並べる／coverflow／X魚眼ビュー／議事録／勤務表）が、親の View だけで出るか。

  • 出た。アンカー・関係・席の譲り合いは無い。配置を決めるのは 1か所（resolveSpace）だけで、 深さ3の倍率は各段の局所倍率の積 0.905797
  • 「手前へ」も Z 軸に書く。置いた順（stack）という View の外の状態が消えた。ただし自由座標で 「一番手前の手前へ」と素直に書くと 触った泡そのものが消える（実測 透明度 0）。 書けるのは焦点の面まで
  • 親を付け替えたら 数え直す（reindex）。呼ばないと先客の逃げ先が古い兄弟で決まった。 議事録を格子にして（4つとも 0,0）よそから1つ落とすと 5個5マス（前は 5個2マス）

直せなかった root で奥へ1回ホイールすると、同じ面にいる泡が 8個のうち7個 まとめて消える（量を小さくしても1回で消える）。 「奥は一番奥の泡まで」は空にしないだけで、同じ面をまとめて越えるのは止めない。

01

スナップは、見えない親の並べ方

隣り合う関係を持たずに、スナップの体験を親子と View だけで保てるか。

  • 保てた。くっつける→並べ替え→加わる→入れ子→外す→親が消える まで通り、相手は 0.0px も跳ばない。 勤務表を並びの子にしても、中の10個は外にいるときと差 0.0000px
  • 決まりは 6つ → 4つ。pin と 奥行き はこの案のものではなかったので土台へ返した
  • 残りは1文に畳めた ——見えない親は体を持たない。箱も、奥行きも、View も、自分のものは何ひとつ持たない。 持っているのは並べ方ひとつだけ。それで穴が塞がった：並びに「自由に置く」を当てても勤務表 0.00px （前は −340px で画面の左外）。8つのプリセット全部 0.00px

直せなかった 詰める空間への差し込みでは、並びが必ず後ろへ伸びる。留まるのは差し込む所より前（0.00px）と並びの外の全部（0.00px）で、 後ろの泡だけが 差し込んだ泡の幅ちょうど 120.00px 動く。詰めるの意味そのものなので、決まりでは塞がらない。

02

レンズは軸ごと。大きさはどう決めるか

X・Y に別々のレンズを付けたとき、1つの数の倍率を、どの軸の倍率から決めるか。

  • min（小さい方）に決まった。鏡（X 枝·平行／Y 世代·魚眼）では 横だけ が 奥行きだけ と 完全に同じ絵（差 0.00px・端 1.00倍・重なり 9組）＝ 「何もしない」に落ちる。答えは「X から」ではなく 曲がっている軸から
  • 理由は式で言える：min は、泡が横の像にも縦の像にも収まる決め方のうち、いちばん大きいもの。 泡の幅 − 像の幅は 奥行きだけ +36.0px／横だけ +7.2px に対し min は 0.0px（下限 0 なら min の重なりは 0組）
  • 「min は 1.0px ずれる」は再現しなかった。背景を掃いた掴んだ点のずれは、焦点に余裕があれば 小さい方・横だけ・横×縦 とも 0.00px。止まる向きでは3つとも同じ px（焦点が止まった分）

直せなかった（min の値段） 合わせなかった軸に隙間が空く（鏡で横に最大 38.5px・平均 17.8px。X が平行なのに泡は縦に合わせて縮むため）。 min の粗ではなく「倍率は1つの数・泡は矩形のまま」からの必然で、消すには矩形をやめるしかない。

03

並べ方：等間隔か、詰めるか

等間隔と詰めるを1つの式で書けるか。どこで破綻するか。

  • 書けた。違うのは 帯の決め方だけ。揃えを全部の空間で1つにすると両方は満たせない （中央にすると勤務表のスタッフとカレンダーが 25px 重なる）
  • 詰める×魚眼 の重なりが 0 になった。式を1つ変えただけ ——泡の大きさを「中心1点の局所倍率」ではなく 「泡の端をレンズに通した像の幅 ÷ 自前の幅」で決める。coverflow・詰める・魚眼で 隙間 0/14/28 とも重なり 0（前は 3/1/0）。トグル総当たり 24通りで、中心の倍率は 20通り重なり、 新式は 0通り。平行のレンズの空間は1つも変わらない
  • 1文：重ならないことを保証するのは詰めるだけ。重なりを作るのはレンズではなく並べ方。 「等間隔だと中の伸びが外に伝わらない」は破綻ではなく定義どおり——等間隔に中身を見させると 帯の幅が中身で決まり、詰めるそのものになる（重なり 7 → 0）

直せなかった 等間隔×魚眼 の重なりは 7 のまま（間隔より広い泡が帯からはみ出す並べ方なので、レンズの写し方では消えない）。 等間隔の「塊」を 泡か帯かも公理だけでは選べない（帯にすると箱が 511 → 634px 片寄る）。トグルのまま。

04

操作は軸に従う

「書けるなら書く／書けないなら視点／なしなら何も起きない」の1文だけで、触る・ドラッグ・ホイールの全部が説明できるか。

  • 「触る」の行を足しても、ルールは1文のまま。表は 4行 → 5行。 5空間ぜんぶ、表の言葉と本物のクリックが一致した（順序＝最前面／自由座標＝焦点の面まで／履歴・なし＝上がらない）
  • 操作を決めるのは軸だけでなく 何を掴んだか。表は 泡／背景 の2列になった（ホイールは掴まないのでいつも視点）
  • 空間を移るのは カーソルの点 の決まりで、軸の決まりではない。軸を止めるならポインタの成分を止める （左へ 330px 引いても泡は 0px・親も変わらない）

直せなかった 「dz<0 は消える」と「Z の焦点は一番奥の泡まで行ける」が合わさると、同じ面に5つ並ぶ外の空間では deltaY 4（焦点Z 0.016）でも 5個消え、見える泡 31 → 1。比べのボタン「自由Zは手前の面で止める」を選ぶと deltaY 100 でも 0個だが、奥の面へ行けなくなる。

勤務表を、公理だけで組む

masa さんが「作れるようになりたい」と言った画面が、特別扱いを足さずに組めるか。

  • 組めた。特別扱い（この場面だけの if・例外）は 0。場面の定義は 19行、 View を決めるのは 6か所、位置は1つも書いていない
  • ⑤ は公理の穴ではなかった。佐藤の箱を 150 → 214（＋64px）にして切ると、佐藤・スタッフ・勤務表がそろって −32px ＝ 伸びのちょうど半分 動く。「位置＝中心」から出る補正
  • 深さ6（見えない親2つを含む）でも倍率は各段の積。佐藤の中でホイールすると佐藤の焦点 Z だけが動き、 ほかの4人・勤務表・カレンダー・世界線は 0.0000px 動かない

06

対照実験：レイアウトとカメラを分ける（案B）

「型＋カメラ」に分けるよくある作り方（B）と、軸ごとの View（A＝公理）を、同じ道具で数えて比べる。

  • 6場面の配置は A と 54個すべて差 0（焦点 0 でも、背景を (116,40) 引いた後でも）。 型の定義 A 12行／B 45行・選ぶセレクタ A 9／B 4・ 組み合わせ A 216,000／B 40
  • 機能を1つ（触ると手前へ）足すと、型を読む分岐は A ＋2 / B ＋1（42→44 と 24→25）。数だけなら B が小さい
  • ただし「重ねて置く」（触ると最前面へ・ずれない）は A はプリセット1行、B は6型のどれでもできない （実測：6型ぜんぶで 奥→手前 が memo1,memo2,memo3 のまま）。 ＝ A の ＋2 は「もう持っている語彙で言えた」ぶん、B の ＋1 は「言えないまま」のぶん

直せなかった A と B のどちらを採るかは決まっていない。分岐の数では B（44 対 25）、言える範囲では A。 両方そのまま載せてある。

まだ決まっていないこと

8件。各案の「直せなかった」から。下の案の番号をクリックすると、その案が開く。

1 ── Z の焦点を、焦点の面で止めるか

止めれば「ホイール1回で同じ面の7個が消える」も「触ると消える」もいっぺんに塞がる （deltaY 100 でも消えた泡 0）。代わりに奥の面へ行けなくなる（奥へ4回ホイールしても焦点 0）。 案4 に比べのボタンがある。masa さん判断待ち。

0400

2 ── 等間隔の「塊」は、泡か、帯か

泡の端から端で測ると端の泡を広げて兄弟が一緒にずれ（−10/−20/−30px）、帯の端から端で測るとずれは 0 になる代わりに 箱が片寄る（勤務表 511 → 634px）。公理だけでは選べずトグルのまま。 「塊を空間のどこに置くか」もまだ無い（いまは必ず中央）。

03

3 ── 等間隔 × 魚眼 の重なりは消せない

詰める×魚眼 は「泡の端をレンズに通す」で 0 になったが、等間隔は 7 のまま。 等間隔は間隔より広い泡が帯からはみ出す並べ方なので、レンズの写し方では消えない （中身を見させると、それは等間隔ではなく詰めるになる）。

03

4 ── 案 A と 案 B のどちらを採るか

同じ絵は両方作れる（54個すべて差 0）。機能を1つ足したときの分岐は A ＋2／B ＋1 で数なら B。 ただし「重ねて置く」は A ＝プリセット1行、B ＝6型のどれでもできない。 数と言える範囲が逆を向いている。

0600

5 ── 詰める空間への差し込みで、後ろが動く

留まるのは差し込む所より前（0.00px）と並びの外の全部（0.00px）。後ろの泡だけが 差し込んだ泡の幅ちょうど 120.00px 動く。これは詰めるの意味そのもので、穴ではない。 受け入れるかどうかだけが残っている。

01

6 ── View そのものを変えたときは pin していない

⑤ が効くのは 付け替えと大きさを変えたときだけ。見えない親のほうは「View を選べない」で塞がった （8つのプリセット全部 0.00px）が、体のある泡の View を変えたときの決まりはまだ無い。

01

7 ── はみ出した中身の持ち主が見分けられない

切り抜かないと決めたので、箱からはみ出した中身が どちらの箱のものか読めない （左右が同じ題名・同じ色だと赤い破線が交差する）。いまは重なりの数（5／7）だけが頼り。 見分けるには「破れの見せ方」が要るが、それは公理の外。

03

8 ── 自由座標の Z では、重なりの上下が決まらない

「手前」は焦点の面までしか書けない（それより手前は透視が消す）ので、自由座標では「最前面」を表せない。 同じ面に来た泡の上下は View から決まらず、描く順の最後の項が決める。 決めたいなら Z に「順序」を刺す（プリセット「重ねて置く」）。
