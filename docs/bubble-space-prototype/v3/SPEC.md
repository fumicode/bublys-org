# bubble-lab v3 共通仕様 — 「親の View だけで並べる」

v3 の各案（`00-core.html` 〜）を作るときの共通の語彙と約束。
**案どうしを比べられるように、ここに書いたことは全案でそろえる。**
案ごとに違えてよいのは「その案で確かめること」の部分だけ。

---

## 0. 公理（案）

> **泡の見え方は、その泡を入れている親の View で決まる。**
> **View は軸（X・Y・Z）ごとに「次元」「並べ方」「レンズ」を持つ。**
> **これが入れ子ごとに繰り返される。**

第1版（`bubble-lab.html`）の公理は「論理座標とレンズの合成だけで決まる」だったが、実際には
**配置の経路が2つ**あった（アンカー＝含む／隣り合う から決まる経路と、次元→レンズの経路）。
v3 は経路を1つにする。**スナップも、内包の中のレイアウトも、coverflow も、すべて親の View。**

masa さんの言葉（2026-09-15）:

- レンズは x軸, y軸, z軸 のそれぞれにつくべき。世界線ビューは X が魚眼、Y は平行
- 勤務表の上に制約、その下にカレンダー、左にスタッフが縦に並ぶ、というレイアウトを作りたい
- バブルAの左にバブルBがスナップしているとき、実はそれらを束ねるバブルXがあり、その中に
  「内包物を左右に並べる」レイアウトが設定されているとみなせる
- レイアウト用の親の X 軸に魚眼レンズを設定すれば coverflow になる
- 「世界線ビュー」は参考にしたコンポーネントの名前でしかない。「X魚眼ビュー」が正確
- Z に何も割り当てていないのにホイールでズームしても意味がない。
  履歴を奥行きにしたとき、ホイールで時間を行き来するのはとても直感的

## 1. 語彙

### 泡（Bubble）

```js
{ id, title, hue,
  size: { w, h },          // 自前の大きさ（手で変えられる）
  parent: "bubble-id" | null,   // null ＝ いちばん外の空間（root）にいる
  free:  { x, y, z },      // 「自由」次元が読む座標
  order: 0,                // 「順序」次元が読む値（兄弟の中での順番）
  cell:  { col, row },     // 「列」「行」次元が読む値
  hist:  0, branch: 0,     // 「履歴」次元が読む値（プロトタイプではダミーでよい）
  view:  View | null,      // 中に泡を入れているなら、その並べ方。null なら外から継ぐ（§4）
  implicit: false,         // スナップで自動的に生まれた見えない親か（案1で使う）
}
```

- **関係（含む・隣り合う）は無い。親子だけ。** 含む＝親になる、隣り合う＝見えない親の並び。
- 中に泡を持つ泡を「**空間を持つ泡**」と呼ぶ。いちばん外の空間 root も同じ扱い（泡ではないが View を持つ）。
- 「開いた」「参照」などの帯は v3 では扱わない（レイアウトの原則と無関係なので棚上げ）。

### 次元（Dimension）— 泡 → 値

| id | ラベル | 読む値 | 書けるか（ドラッグで何が起きるか） |
|---|---|---|---|
| `none` | なし | 常に 0 | 何も起きない |
| `free.x` `free.y` `free.z` | 自由X / 自由Y / 自由Z | `free.*` | **動く**（座標に足す） |
| `order` | 順序 | `order` | **並べ替わる**（カーソルの下の位置へ差し込む） |
| `col` `row` | 列 / 行 | `cell.col` / `cell.row` | **別のマスへ移る** |
| `history.index` | 履歴の世代 | `hist` | 書けない → **視点が動く** |
| `history.age` | 履歴の古さ | 同じ空間の最大 `hist` − `hist` | 書けない → 視点が動く |
| `history.branch` | 履歴の枝 | `branch` | 書けない → 視点が動く |

```js
{ id, label, read(b, space) => number, write: null | "coord" | "reorder" | "cell" }
```

- **derived 次元は、どの空間の値を読むのかを知っている**（v2 で踏んだ：「履歴の古さ」を全泡横断の最大値で
  測ると無関係な空間の版数に引きずられた）。`read(b, space)` と空間を受け取る。

### 並べ方（Arrange）— 値 → 空間の中での位置

| id | ラベル | 位置の決め方 |
|---|---|---|
| `as-is` | そのまま | 値をそのまま px として使う（自由次元用） |
| `equal` | 等間隔 | 値 × 間隔（`step` px）。coverflow・世界線の世代 |
| `pack` | 詰める | **値ごとに帯を作り、帯の幅はその値を持つ泡の中で一番大きいもの。帯を値の順に隙間 14px で並べる** |

- `pack` は `order`（値が重ならない）でも `col`（同じ列に複数いる）でも同じ式で動く。
- `equal` と `pack` は、並んだ塊の中央が空間の中心に来るように置く（焦点 0 のとき中央ぞろえ）。
- 帯の中での揃え（`align`: `start` 始端／`center` 中央）と、詰めるの帯どうしの隙間（`gap`）は、
  `step` と同じく **View の軸が持つ**。全空間で1つに決めると両立しない（案3 で踏んだ：始端でないと勤務表の制約と
  カレンダーの左端がそろわず、中央でないと coverflow の横長の写真が帯からはみ出して隣に重なる）。既定は始端。

> **重ならないことを保証するのは `pack` だけ。**
> `equal` は「帯の幅は間隔。中身の大きさを見ない」が定義なので、間隔より広い泡は帯からはみ出して隣と重なる
> （coverflow はそれを見せる並べ方）。`equal` に中身を見させると帯の幅が中身で決まり、「値×間隔」が消えて
> `pack`（下限つき）になる ── つまり **`equal` をやめることにしかならない**（案3 で実際に作って測った）。
> 同じ理由で、**入れ子の中の箱が伸びたことが外に伝わるのは、外が `pack` のときだけ。伝わらないのは破綻ではなく定義**。

> 未決：`equal` の「塊」を **泡の端から端** と **帯の端から端** のどちらで測るか。公理だけでは選べない。
> 泡で測ると端の泡を広げたとき兄弟が一緒にずれ（勤務表・等間隔のカレンダーで −10/−20/−30px）、
> 帯で測るとずれは 0 になる代わりに箱が片寄る（勤務表 511 → 634px）。既定は「泡の端から端」。
> **「塊を空間のどこに置くか」も、まだ無い**（いまは必ず中央）。

### レンズ（Lens）— 位置 → 画面。**軸ごとに1つ**

| 軸 | id | ラベル | 式（u = 位置 − 焦点, H = 空間の半幅） |
|---|---|---|---|
| X/Y | `parallel` | 平行 | 画面 = u、局所倍率 1 |
| X/Y | `fisheye` | 魚眼 | 画面 = H·tanh(u/H)、局所倍率 sech²(u/H)（中心で 1、端で飽和） |
| Z | `perspective` | 透視 | 倍率 m = 1/(1 + 0.26·dz)、XY を消失点へ m で寄せる。dz<0 は透明にして消す（第1版 制約02） |
| Z | `flat` | 平行 | Z を見た目に使わない（倍率 1） |

- **泡の像は、泡の端をレンズに通した間。** 軸ごとに 倍率 ＝（像の幅）÷（自前の幅）、位置 ＝（像の中点）。
  中心1点の局所倍率で一様に縮めると、帯の像と泡の像が別の式で縮むので噛み合わない
  （案3 の実測：詰める×魚眼で 隙間14 のとき端の隣と −1.7px 食い込む。泡の端を通すと 0）。
  **レンズは1次元の単調な関数なので、位置が重ならない泡は像も重ならない。重なりを作るのはレンズではなく並べ方。**
  平行のレンズでは 像の幅÷幅 がちょうど 1 なので、平行の空間は1つも変わらない。
  （実装は案2 `02-lens-per-axis.html` と案3 `03-pack-or-equal.html` の `projectIn()`。
  土台 `00-core.html` と案1・案4・案5・案6 は中心1点の局所倍率のまま ── 魚眼と詰めるが同じ軸で重なる場面が
  その5つに無いので、絵は変わらない。**そろえること自体は目的ではない**）
- **X/Y のレンズは1次元の関数なので、逆関数（unproject）が必ず書ける**。第1版の制約B
  「逆変換を必ず持つ」は、軸ごとにしたことで自然に満たされる。
- 消失点は焦点と別に持つ（第1版 制約01）。空間ごとに持つ。root は画面中心 + (−130, −165)。
- 目の位置（`bubble-lab-v2` の「目で見る」）は、**レンズの ctx を作る関数1か所だけ**で足せるようにしておく
  （状態には書き込まない）。v3 の各案では目の追跡そのものは移植しなくてよい。

### View

```js
{
  x: { dim: "free.x",  arrange: "as-is", lens: "parallel", step: 260 },
  y: { dim: "free.y",  arrange: "as-is", lens: "parallel", step: 180 },
  z: { dim: "free.z",  arrange: "as-is", lens: "perspective" },
  focus: { x: 0, y: 0, z: 0 },   // その空間で「いまどこを見ているか」。空間ごとに自分のもの
}
```

### 大きさの倍率（1つの数）

泡は矩形のまま拡大縮小する。だから倍率は1つの数で、**合わせられる軸は1つだけ**。
合わせるのは **曲がっている軸**。その一般形が min:

```
scale = 親の scale × Z の倍率 × min(X の像の倍率, Y の像の倍率)
```

軸ごとの倍率は **泡の像**（泡の端をレンズに通した間の幅 ÷ 自前の幅）。平行のレンズでは 1。

- 平行のレンズは倍率がいつも 1 なので **min から落ちる**。だから「どちらの軸が曲がっているか」を
  View に書かなくても、min が自動で曲がっている軸を選ぶ。
- **min は、泡が横の像にも縦の像にも収まる決め方のうち、いちばん大きいもの**（min(kx,ky) ≤ kx かつ ≤ ky）。
  レンズは単調なので、像が重ならない泡は、像に収まっているかぎり重ならない。**ここは測らなくても式から言える。**
- 本物の世界線ビュー `WorldLinesCanvasView.tsx:157-165` は X だけで決めている。それが正しく見えるのは、
  そこで曲がっているのがたまたま X だからで、**軸を入れ替えると破れる**。

> 実測（案2 `02-lens-per-axis.html`、`_check/02-recheck.mjs`。世界線ツリー 版20・枝3、端での下限 0.25）：
> **X 枝・平行／Y 世代・魚眼の「鏡」では、`X だけ` が `Z だけ` と完全に同じ絵になる（差 0.00px）**。
> 端の泡も原寸のまま（端 1.00倍）で 重なり 9組・読める 15/20、縦に送れる焦点は 123（並びは 374）。
> `min` は 端 0.44倍・重なり 2組・読める 11/20 で、送れる焦点が 247 に広がる。
> 横も縦も曲がる XY魚眼では `min` は `X だけ` と同じ数（端 0.43倍・重なり 5組・読める 11/20）で縮みすぎず、
> 縦に焦点を端まで送れる（68/68 対 51/68）。`kx·ky` は縮みすぎて読めるのが3つ減る（8/20）。
> 泡の幅 − 像の幅（＋なら像から食み出す。下限 0）：`Z だけ` は 横 +36.0px・縦 +7.6px、`X だけ` は 縦 +7.2px
> （鏡では +17.9px）食み出すのに対し、**`min` と `kx·ky` は 0.0px**。下限 0 なら `min` の重なりは 0組。
> `kx·ky` は収まるが必要以上に小さく、読めるのが 3〜7 つ減る。
> min が入れ替わる線は中身の箱の対角線（× の形）で、そこは**折れ目であって段差ではない**（掃いても絵が飛ばない）。
> 背景を掴んで掃いたときの掴んだ点のずれも `X だけ` と同じ（焦点に余裕があれば 0.00px）。

> min の値段：**合わせなかった軸に隙間が空く**（鏡で横に最大 38.5px・平均 17.8px。X が平行なのに泡は縦に合わせて縮むため）。
> これは min の粗ではなく「倍率は1つの数・泡は矩形のまま」からの必然で、消すには軸ごとに別倍率＝矩形をやめるしかない。

## 2. 解く順番（1フレーム）

```
resolveSpace(空間, 空間を持つ泡の画面上の配置 host):
  V = viewOf(空間)                                  ← §4 継承
  各軸について:
    値     = V[軸].dim.read(泡, 空間)
    位置   = V[軸].arrange(値, 兄弟の大きさ)          ← pack は兄弟全員を見る
    画面   = V[軸].lens(位置 − 焦点)                  ← X, Y は平面上で。そのあと Z で消失点へ寄せる
  泡のローカル配置 { x, y, scale }
  ★ 合成はここ1回だけ：
    画面x = host.left + ローカルx × host.scale
    scale = host.scale × ローカルscale
  中に空間を持つ泡なら resolveSpace(その泡, その配置) を再帰
```

- 深さ n でも `scale` は数値1つ（v2 で実測済み：0.4902 × 0.6579 × 0.7937 = 0.255950）。
- 空間の中身の座標系：空間を持つ泡の**中身の箱**（ヘッダ 24px の下）の中心が原点。
- `equal` / `pack` の軸では、空間を持つ泡の箱は中身が収まるまで伸びる（＋余白 14px）。`as-is` の軸では自前の大きさ。
- **描く順**：空間ごとに Z で奥から手前へ1回ソート。中身は空間を持つ泡の直後に描く。**切り抜きはしない**（masa さん：窮屈）。
  式は `(p, q) => q.dz - p.dz || p.target.scale - q.target.scale || p.i - q.i`。
  **「置いた順」のような View の外の状態は持たない。** 3つとも同じなら上下は View から決まらない（＝ Z に「順序」を刺す）。
- 当たり判定は描いた順の逆から（内側・手前が勝つ）。

## 3. 操作 — 「操作は軸に従う」

| 入力 | 軸 | 起きること |
|---|---|---|
| ドラッグ横 | X | X の次元が書けるなら書く（動く・並べ替わる・マスを移る）。書けないなら**その空間の焦点 X が動く**。なしなら何も起きない |
| ドラッグ縦 | Y | 同上 |
| ホイール | Z | カーソルの下の空間の焦点 Z が動く。**Z の次元が「なし」なら何も起きない**（ヒントにそう出す） |
| 背景ドラッグ | X,Y | カーソルの下の空間の焦点が動く |
| 右下の角をドラッグ | — | 大きさを変える |

- **ドラッグの逆変換は軸ごと**：画面の移動量 → そのレンズの unproject → 空間の中の移動量。
  書き込む先は**その軸に刺さっている次元**（`free.x` 決め打ちにしない。v2 の穴：X に「自由Y」を刺すと横に引いて縦に動いた）。
- ドラッグの判定は**掴んだ泡がいる空間**の View で決める。焦点を動かすときは**掴んだ泡がいる空間**の焦点。
- 並べ替え・マス移動は、ドラッグ中はカーソルに泡がついてきて、差し込まれる位置に印を出し、離したら確定。

### 触っていない泡は、画面の上で動かない

> **泡の位置は、箱の中心。**
> **だから中身が変わって箱が伸び縮みしたら、触っていない泡の見えている場所を保つように、位置を書き直す。**

公理は「値 → 見え」を決める。これはその逆で、**「さっきの見えを保つように、値を書き直す」**もの。
別の仕組みではなく、**「位置＝中心」を選んだことから必然的に出てくる補正**。

> 実測（`_check/pin-why.mjs`）：佐藤の箱を 150 → 214（＋64px）にしたとき、書き直しを切ると
> 佐藤・スタッフ・勤務表がそろって **−32px ＝ 伸びのちょうど半分**動いた。
> 半分になるのは、箱が中心を軸に両側へ伸びるから。書き直せば 0.0px。

**誰を留めるか**（ここを1つ間違えると、入れ子の外側ごと動く）:

- 留めるのは、**空間の中身が変わったとき**だけ（泡が入った・出た・大きさが変わった）
- 同じ空間の中での**並べ替えは留めない**（帯が入れ替わるだけで、塊も箱も変わらないため）
- 書き先は、その泡から**外へたどって最初に「その軸が自由な空間」にいる泡**の座標
- **詰める空間への差し込みでは、留められるのは「差し込む所より前（先頭側）」だけ。**
  前が留まり、並びは後ろへ伸びる。後ろの泡は**差し込んだ泡の幅ちょうど**動く
  （実測 案1：幅 120 の泡を差し込むと 前の泡 0.00px・並びの外のすべて 0.00px・後ろの泡だけ 120.00px）。
  これは穴ではなく、**詰めるの意味そのもの**。
- **View そのものを変えたときは留めていない**（付け替えと大きさのときだけ）。ここは未決。

> なぜ「位置＝左上」にしないか：中心は、レンズ・消失点・魚眼の半幅・当たり判定まで一本で通っている。
> そこだけ崩すと全部を直すことになる。**中心を貫き、補正を持つ**ほうを選んだ。
>
> 参考：「塊を始端に留める」だけでは破綻する。箱が「中心からの最大距離 × 2」で測られているので、
> 中身だけ端へ寄せると箱が倍になり、入れ子で増幅する（勤務表 528×572 → 1888×1896、画面に残る泡が 53 → 2）。

### 触った泡は手前へ

> **触った泡は、その空間の Z 軸の次元が書けるなら、そこへ書く。**

重なった泡の上下は、「置いた順」のような View の外の状態では持たない。**「手前」は奥行きのことなので、Z 軸に書く。**
書き込みは §3 の表と同じ動詞（`reorder` / `coord`）を使う。新しい仕組みは足さない。

| その空間の Z の次元 | 触ったとき |
|---|---|
| `order`（順序） | 最前面（0）へ並べ替えて詰め直す。値は 0.. に収まるので、何度触ってもずれていかない |
| `free.z`（自由座標） | **焦点の面まで上がって、そこで止まる。それより手前へは出せない**（透視が dz<0 を消すため）。＝ **自由座標の Z では「最前面」を表せない**。同じ面に来た兄弟の上下は決まらない |
| `history.*`（履歴） | 書けないので上がらない。**履歴の並びは、触っても順番が変わらない** |
| `none`（なし） | 何も起きない |

> **Z の「手前」の端は焦点の面。** 焦点より手前は写らない（§1 のレンズ）ので、そこより手前へは **書けないし、送れない**。
> 書き先を止めないと、触った泡そのものが消える（実測：`free.z` 1 → −0.15、透明度 0）。
> 焦点を止めないと、ホイール1目盛りで同じ面の兄弟がまとめて消える
> （実測：deltaY 4／焦点Z 0.016 で、root の 8個中 7個・見える泡 54 → 23）。
> ただし焦点まで止めると、奥の面へ行けなくなる（実測：奥へ4回ホイールしても焦点 0）。
> **書き先は止めた。焦点を止めるかどうかは、まだ決めていない**（案4 に比べのボタンとして置いてある。既定は「消す」）。

**重なりの上下を View の中で決めたいなら、Z に「順序」を刺す**（プリセット「重ねて置く」）。
これは旧 bubble-ui の `layers: string[][]`（Z が配列の添字）と同じもので、「最前面へ上げる」は Z 軸での並べ替えにあたる。

> 実測（`_check/raise.mjs`）：重ねて置く＝触った泡が最前面へ／横に並べる（Z なし）＝変わらない／
> 議事録（Z 履歴）＝版の順番は変わらない。完全に隠れた泡はクリックで当たらないので上がらない（重ねる UI として当然）。

## 4. 継承

- `view` を持つ空間はそれを使う。
- 持たない空間は、既定で**並べ方（次元・並べ方・レンズ）を外から継ぐ**。**焦点は継がない**（v2 で踏んだ：継ぐと窓が自分の視点を失う）。
- 軸セレクタを変えると、**選択中の泡がいる空間**が自前の View を持つ（継いでいたなら今の見え方を写し取ってから変える）。

### 見えない親は体を持たない

> **見えない親（`implicit: true`）は、箱も、奥行きも、View も、自分のものは何ひとつ持たない。**
> **持っているのは並べ方ひとつだけ。**

- 箱はヘッダ 0・余白 0 で、**どの並べ方でも中身ぴったり**（「そのままの軸は自前の大きさ」は体のある泡の話）。
- **Z は軸まるごと外の窓のもの**（次元・並べ方・レンズ・焦点のぜんぶ）。焦点だけ通すと、並びの中だけ透視が残る。
- **View を選べない。** 軸セレクタもプリセットも、外へたどった窓へ回る。
- 当たるのは外周だけ。空間の出入りも、外へたどった窓で数える。

> 実測（案1）：「View を選べない」にする前は、並びに「自由に置く」を当てると中の泡が持ったままの自由座標で
> 置かれ、勤務表が **−340px** 飛んで画面の外へ出た。決まりにしたあとは **0.00px**（8つのプリセットすべて）。

## 6. ファイルの約束

- **1案 = 1ファイルの HTML**。ビルド不要、`file://` で開くだけで動く。**ネットワークを使わない**（CDN も読まない）
- 置き場所：`docs/bubble-space-prototype/v3/NN-名前.html`
- ファイル冒頭のコメントに：公理（案）／この案で確かめること／**踏んだこと**（作って試して分かったこと。机上の話は書かない）
- コンソールエラーを出さない
- **検証用の口** `window.__lab` を必ず出す（自動で操作して確かめるため）:

```js
window.__lab = {
  select(id),                 // 泡を選ぶ
  selectedId(),
  bubbles(),                  // 泡の配列（生の状態）
  viewOf(spaceId),            // その空間で効いている View（継承を解いたもの）。root は "root"
  setAxis(spaceId, axis, patch),   // 例 setAxis("kinmu", "x", { lens: "fisheye" })
  preset(name, spaceId),      // プリセットを空間に当てる
  placements(),               // 画面上の配置 [{ id, x, y, w, h, scale, depth, space }]（x,y は画面上の左上、w,h は画面上の大きさ）
  rectOf(id),                 // 画面上の矩形 { x, y, w, h }
  headerPointOf(id),          // ドラッグを始められる点（ヘッダの中）の画面座標 { x, y }
  focusOf(spaceId),
  frame(),                    // 補間を1フレーム進める（テストで待たずに進めるため）
  settle(),                   // 補間が落ち着くまで進める
}
```

- 補間（見た目のなめらかさ）は入れてよいが、`__lab.settle()` で即座に落ち着かせられること
- 画面の大きさは 1440×900 で見て破綻しないこと
