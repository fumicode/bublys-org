## 2026-09-19

### 触ると、泡ではなく視点が動く ★ 規則②が変わった

> 「触った泡は手前へ、は多分、微妙だと思う。どちらかというと、**触った泡の方にカメラが寄っていく**感じがいいと思う」

**値を1つも書かなくなった。** これで消えたもの:

- `raise`（触ったとき Z に書く動詞）
- 泡の `order` を X と Z で取り合う問題 ── **「横に並べる」と「触ると主役が変わる」が同時に成り立つ**
- ⑤ との緊張（値を書かないので、触っていない泡は定義上動かない）

実測：coverflow で焦点 X を送ると倍率が `0.31 … 0.98 … 0.31` → `0.03 … 0.98` に変わり、
**泡の値（順序・自由X）は1つも変わらない**。

### 端での下限 ── ★ 入れたが、翌日に取り消した

> 「（右端が隠れてもいいと言ったのは）**あるバブルAの右端が、より手前のバブルBの左側によって隠されても**、
> 後に開いた B にある程度関心事がうつっているのだから、A が多少隠れても構わない場合もあるだろう、ということ」

**「覆われる」と「潰れる」は別物だった。** ここまでは合っている。

★ **ただし「潰れて読めないのは駄目」は masa さんの言葉ではなく、僕（Claude）の解釈だった。**
masa さんが言ったのは「覆われるのは構わない」までで、「潰れるのは駄目」とは言っていない。
翌日そこを正された:

> 「別に**奥に行ったバブルは読めなくてもいい**よ。**雰囲気だけでも残ってることに意味がある**。
> だからこれは全然 OK。ある程度小さくなったバブルは**描画さえしなくていい**し」

**だから下限は要らない。** 入れたことで起きていた不都合も、これで消える:

| 下限を入れて起きたこと | 取り消すと |
|---|---|
| 触った泡が中央まで来ない（焦点が 204 まで届かず 67.1 で止まる） | **届く**（実測 204.0・倍率 0.98） |
| `pack` × 魚眼 が重なるようになった（食い込み −8.3〜−16.6px。隙間による） | **重ならなくなる**（像の幅で描くので） |
| テストの期待値がずれた | 元に戻る |

**代わりに入れるのは「描画の下限」。** 小さくなりすぎた泡は**描かない**（規則ではなく ui の話。
既にある「題名は 6.5px を切ったら描かない」の延長）。

下限そのものは v3 にはあった（`v3/05-kinmuhyo.html` の `SIZE_FLOOR = 0.32`）。
あれは**本物の世界線ビューの数字**で、丸いノードに題名を出さないから足りていた。
題名を出す泡では `12 × 0.32 = 3.84px` で読めない ── **そもそも「読める下限」ではなかった。**

### 新しい泡は、opener の兄弟

`openingPosition` は**3役を兼ねていた**（どこに置くか／開いてよいか／膜を出すか）。分ける:

| いま | これから |
|---|---|
| どこに置くか | **親の View が決める**（①④）。props から消える |
| 開いてよいか | `url` が解けるかどうか |
| 膜を出すか | **掴めるかどうか**だけで決まる |

ダブルクリックとドロップは**もともと同じ道**だった（`openBubble` の第3引数が違うだけ）。
コミット `1f3987b7` に「ダブルクリックが『開いて』なら、ドロップは『ここに開いて』」と書いてある。

### ポップアップは、世界線の打ち消しスナップで戻る

> 「ポップアップは、すぐに元のページにもどっていく前提。あと、比較的小さい。
> だから、**親は下がるには下がって、ポップアップバブルが手前に出る。閉じたら、また親は元の位置に上がる**」

`world-line-graph` に既にある規則を使う:

```js
// 打ち消しスナップ：見込み状態が祖先（＝戻る）／既存の子（＝進む）と一致するなら、
// 新ノードを作らず apex をそのノードへ移す
const snapTarget = this.findSnapTarget(apex.id, prospectHash);
if (snapTarget !== null) return this.moveTo(snapTarget);
```

**カメラは、ハッシュに入れず、ノードに紐づける。**

- 状態に入れると：閉じても**カメラが動いたまま**なのでハッシュが一致せず、戻らない
- ノードに紐づけると：泡の状態が一致 → 古いノードへスナップ → **そのノードのカメラを当てる** → 視点も戻る

カメラは「その世界が**どうだったか**」ではなく「その世界を**どこから見ていたか**」なので、同一性には入らない。

これで **「焦点を世界線に載せるか」の2択に third があった**ことになる ── 載せる／載せない ではなく、
**同一性には載せず、ノードには載せる**。

あわせて、`intent` の仕組みで「16歩引くとノードが16個」も起きない:

> 世界線のノードは**ユーザーが手を下した1回につき1つ**。意図は pointerdown で開き、次の入力まで閉じない。
> 開いている間に配置が何回変わってもノードは増えず、2回目以降は同じノードを書き換える（amend）。

`intentLabel` の例に既に `open:… / close:…` がある。

### 泡の中身と、子の泡は、別物にする

- **勤務表のセルは泡にしない**（全部泡にすると重すぎる）。ただし **ObjectView ではあってよい**
- そのために **`<table>` ではなく CSS grid** で組む（`<tr>` は table fixup で ObjectView に包めない。実害が出ている）
- **ObjectView は `bubble-layout`（domain）に入らない。** 入るのは動詞だけ ──「この空間の、この点に、新しい泡を置く」
  ObjectView はそれを呼ぶ人の1人（ほかに宇宙のドロップゾーン、ツールバー、ポケット）
- 泡の中身は `renderBubble(id) => ReactNode` で外から渡す。**子の泡は domain の木だけが知っている**
  （`<Bubble><Bubble/></Bubble>` と書けるようにすると、木が React と domain の2箇所にできて剥がせなくなる）

### 補間は CSS transition

> 「いったん CSS transition でいいんじゃない？やってみて重かったりしたら考える。
> （たとえば、中身の描画を完全にやめて泡の枠だけ動かして、移動が終わったら中身を描画しなおす、とか）」

毎フレーム書くのが `transform` 1行だけなので、transition は1行で載る。
掴んでいる泡だけ transition を切る（指から遅れるため）。

重くなったときの逃げ道は実測済み ── 画像に焼く手は、既存 `bubbles-ui`（4段グラデ＋影4枚＋`backdrop-filter`）で
**2.2倍**（54→118fps）。いまの泡は中身が軽すぎて焼き代のほうが高い。

### 焦点より手前は、消す。消えたものは縁に積む ★ 未決が1つ減った

> 「消して。で、自分より手前にバブルがある場合には、**右端に「手前の泡スタック」みたいなものがあって
> スタックにアイコンが積まれる**形にしたらどうだろうか？」

「消える」が怖かったのは、消えたものが**どこにも無くなる**からだった。**縁に積めば怖くない。**

- **止める**は採らない ── 奥の面へ行けなくなる（実測：奥へ4回まわしても焦点 0）
- **薄くするだけ**も採らない ── 越えた面が倍率 20（640×520px）の板になって画面を覆う（実測）

#### ★ ポケットとは別物（ここを一度取り違えた）

> 「ポケットは、**オブジェクトのクリップボード**のようなもの。
> 今僕が言ったのは、**view の要素が視界の外に出た（とりわけ Z 軸的に）場合に、そこに戻れるように積む**というもの。
> **積むという点しか似ていない**と思う」

| | ポケット | 手前の泡スタック |
|---|---|---|
| 何の話か | **中身**（オブジェクト） | **見え**（view） |
| どうやって入るか | **置く**（クリップボード） | **置かない。** カメラがそこにいるから出ている |
| 状態を持つか | **持つ**（置いたら残る） | **持たない。** カメラを戻せば勝手に空になる |

**状態を持たないことは実測済み**（`_carryover/outofview.mjs`）:

```
はじめ        手前へ抜けた 0
ホイール1回    手前へ抜けた 1
ホイール3回    手前へ抜けた 2   ← g2 g3
戻した        手前へ抜けた 0   ★ 勝手に空になった
```

**だから「積む／降ろす」という操作も要らない。スタックは、カメラの位置の関数。**

#### 誰が知っているか

`resolveWorld` は既に `alpha` と `vis` を返している（`placements()` の鍵は
`id x y w h scale local depth space alpha vis implicit`）。**「手前へ抜けた」＝ `alpha === 0` で取れる。**

つまり **domain はもう知っている。ui が決めるのは「どこに、どう描くか」だけ。**
（規則は増えない。新しい状態も増えない）

#### 決めた

- **積まれるのは、その空間の中だけ**（入れ子の奥までは拾わない）
- **アイコンを押すと、カメラが戻る**（触ると視点が寄る、と同じ枝）

> 「いずれは、**空間をぐにゃーんって曲げて、戻る前と戻った後を同じ画面にいさせたく**なることもあるかもしれないけど」

★ これは**規則に置き場所がある**。魚眼はまさに「遠いものを潰して画面に残す」ための曲げで、
いまは X/Y にしか無い（Z は `perspective` と `flat` だけ）。**Z にもう1つレンズを足す**のが自然な置き場所。
いまはやらない。

#### 同じ形の問題がもう1つある

「画面の外へ出て掴めない」（持ち越し中）も、**「視界の外に出たものが行方不明になる」という同じ形**。
`placements()` の矩形と窓を比べるだけで取れるので、同じ仕掛けで拾える可能性がある。
ただし**今回の実測では画面の外へ出た泡は 0 個**だったので、そちらは未検証。

### 描く下限 ── ★ 5.0px に決まった

> 「ある程度小さくなったバブルは**描画さえしなくていい**し」

**規則ではなく ui の話。** domain（`bubble-layout`）には入れていない。`resolveWorld` は今までどおり
`placements` を返すだけで、下限を 0→3→5→10→16→20px と動かしても **`placements` は1バイトも変わらない**（実測）。

**測るものは「倍率」ではなく「画面の px」**（短辺 `min(w, h)`）。既にある「題名は 6.5px を切ったら描かない」
（`MARK_MIN`）と同じ物差しにそろえた。

**5.0px の根拠**（実測）。枠は倍率によらず画面で 1.10px（`--rw` × `--k` で相殺される）。
短辺 5.0px なら `1.1 + 2.8 + 1.1` で、**中身の面が枠2本より広い**。ここを切ると泡は
「色のついた面」ではなく「線の切れはし」になる。7〜8倍に拡大して目でも見た ──
2.9px は輪郭だけの染み、5.9px は色の面として在る、7.4px は角丸の小箱。

★ **低い側に置いた決め手は「消しすぎ」のほう。** カレンダーを 列·等間隔·魚眼 で潰した場面で、日14個が残る数：

```
0px 14/14    5px 14/14    10px 10/14    16px 0/14    20px 0/14
```

16px だと**入れ物（緑の箱）だけ残って中身が空になる** ── まさに「雰囲気ごと消える」。
上げるのはつまみでいつでもできるので、低い側に置いた。

> 「**下限の数は後で適当に決められるでしょ。5px で OK**」

つまみ（`__lab.setDrawMin` ／ ツールバーの range 0〜20px）は**残す**。いつでも動かせる。

`__lab.setDrawMin(px)`／ツールバーの range（0〜20px・0.5 刻み。0 で「なし」）。覚えさせていないので開き直すと 5.0px に戻る。

### 描かなかった泡をスタックに積むか ── ★ 積まない、に決まった

> 「**描かなかった泡も積まないで OK**」

**A（積まない）。** 切り替えは残してある（`__lab.setStackTiny` ／ ボタン「小さいのも積む」）が、既定が答え。
**「積まれるのはその空間の中だけ」も、これで触らずに済む**（下の 1 が要らなくなった）。
札は点線（小さすぎ）と実線（手前へ抜けた）で分かれ、見出しも「手前 N ／ 小 M」と割れる。

選ぶときに効きそうなこと（どれも実測）:

1. **B にしても、たいてい札は出てこない。** スタックは「積まれるのは、その空間の中だけ」という決まり。
   ところが小さく潰れた泡は入れ子の奥にいることが多く、**選択が外にあると B でも 0**。
   同じ画面・同じ2個が消えているのに、選択を写真からメモへ移しただけで札が消える。
   **B を採るなら「その空間の中だけ」も一緒に決め直すことになる。**
2. **A と B は、消えた理由が逆向き。** 手前へ抜けた＝**カメラを戻せば**必ず戻る。小さすぎ＝**カメラを寄せれば**戻る。
   押したときの動き（`focusOn`）は同じなので混ぜても壊れないが、意味は逆。
3. **気づく口はもう1つある。** ツールバーの読みが常に「5.0px　描かない 2」と全空間ぶんの数を出す。
   札が 0 のときもこの数は 2 のまま。**減ったことに気づけるのは、いまのところこれだけ。**

## 言葉づかい

**「軸に次元を刺す」は僕（Claude）の造語で、日本語として変だった。**
正しくは「**その軸が読む値を選ぶ**」。泡は `free` `order` `cell` `hist` を持っていて、
空間の View は軸ごとに「どれを読むか」を1つ選ぶ。`order` は泡に1つしかないので、
同じ空間の中で X と Z の両方が読むと連動してしまう ── というのが「取り合い」の中身だった。
