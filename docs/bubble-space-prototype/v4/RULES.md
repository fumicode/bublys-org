# 泡のならべかた

v3 の7案で踏んで、残ったものだけ。（踏んだ記録は `../v3/` にある）

---

## 規則はこれで全部

> **① 泡の見え方は、その泡を入れている親の View で決まる。**
> **View は軸（X・Y・Z）ごとに「次元・並べ方・レンズ」を持つ。これが入れ子ごとに繰り返される。**
>
> **② 操作は、軸と、何を掴んだかで決まる。**
>
> **③ 見えない親は、体を持たない。**
>
> **④ 並べるとは、値ごとに帯を作り、帯の中に揃えて置き、塊の中央を空間の中心に置くこと。**
>
> **⑤ 触っていない泡は、画面の上で動かない。**

```
              ①  ②  ③  ④
   値  ──────────────────────▶  見え
      ◀──────────────────────
                  ⑤
```

**①〜④は「値 → 見え」を決める。⑤だけが逆で、「さっきの見えを保つように、値を書き直す」。**

⑤は別の仕組みではなく、**「泡の位置＝箱の中心」を選んだことから必然的に出てくる補正**。

---

## 泡が持つもの

```js
{ id, title, hue,
  size:   { w, h },              // 自前の大きさ
  parent: "bubble-id" | null,    // null ＝ いちばん外の空間
  free:   { x, y, z },           // 「自由」次元が読む
  order:  0,                     // 「順序」次元が読む
  cell:   { col, row },          // 「列」「行」次元が読む
  hist: 0, branch: 0,            // 「履歴」次元が読む
  view:   View | null,           // 中に泡を入れているなら、その並べ方。null なら外から継ぐ
  implicit: false,               // スナップで生まれた見えない親か
}
```

**持たないもの：関係（含む・隣り合う）／アンカー／置いた順／レイヤー。**
含む＝親になる。隣り合う＝見えない親の並び。手前＝Z 軸に書く。

## ① 公理

### 次元 ── 泡 → 値

| id | 読む | ドラッグで何が起きるか |
|---|---|---|
| `none` | 常に 0 | 何も起きない |
| `free.x` `free.y` `free.z` | `free.*` | **動く** |
| `order` | `order` | **並べ替わる** |
| `col` `row` | `cell.*` | **別のマスへ移る** |
| `history.index` `.age` `.branch` | `hist` `branch` | 書けない → **視点が動く** |

`read(b, space)` は空間を受け取る。「履歴の古さ」は、**その空間の**最大世代から測る。

### 並べ方 ── 値 → 空間の中での位置

| id | 帯の幅 |
|---|---|
| `as-is` そのまま | 帯を作らない。値をそのまま px |
| `equal` 等間隔 | **間隔（`step`）**。中身の大きさを見ない |
| `pack` 詰める | **その値を持つ泡の中で一番大きいもの**。隙間（`gap`）で続ける |

**重ならないことを保証するのは `pack` だけ。**
`equal` に中身を見させると、帯の幅が中身で決まって「値×間隔」が消える ── つまり `pack` になる。
同じ理由で、**入れ子の中の箱が伸びたことが外に伝わるのは、外が `pack` のときだけ。**

帯の中の揃え（`align`）と隙間（`gap`）は、`step` と同じく **View の軸が持つ**。

### レンズ ── 位置 → 画面。**軸ごとに1つ**

| 軸 | id | 式（u = 位置 − 焦点、H = 空間の半幅） |
|---|---|---|
| X/Y | `parallel` 平行 | 画面 = u |
| X/Y | `fisheye` 魚眼 | 画面 = H·tanh(u/H) |
| Z | `perspective` 透視 | 倍率 m = 1/(1 + 0.26·dz)。消失点へ m で寄せる。**dz<0 は消す** |
| Z | `flat` 平行 | Z を見た目に使わない |

**泡の像は、泡の端をレンズに通した間。** 軸ごとに 倍率 ＝ 像の幅 ÷ 自前の幅、位置 ＝ 像の中点。

> **レンズは1次元の単調な関数なので、位置が重ならない泡は、像も重ならない。**
> **重なりを作るのはレンズではなく並べ方。**


X/Y のレンズは1次元なので、**逆関数が必ず書ける**。消失点は焦点と別に持つ。

> **焦点より手前（`dz<0`）は消す。止めない。**
> 触るとカメラが寄るので、奥の泡を触ると手前のものが消える。それでよい ──
> **消えたものは、画面の縁に積んで拾えるようにする（ui の仕事。規則には無い）。**
> 止めるほうは「奥の面へ行けなくなる」（実測：奥へ4回まわしても焦点 0）ので採らない。
> 「薄くするだけ」は測って駄目だった（越えた面は倍率 20・640×520px の板になって画面を覆う）。

### 大きさの倍率 ── 1つの数

泡は矩形のまま拡大縮小する。だから倍率は1つの数で、**合わせられる軸は1つだけ**。

```
scale = 親の scale × Z の倍率 × min(X の像の倍率, Y の像の倍率)
```

- 平行のレンズは倍率がいつも 1 なので **min から落ちる**。だから「どちらの軸が曲がっているか」を書かなくてよい。
- **min は、泡が横の像にも縦の像にも収まる決め方のうち、いちばん大きいもの。**

**端での下限は持たない。** 焦点を送れば端は 0 まで潰れる。**それでよい。**

> 「奥に行ったバブルは読めなくてもいい。**雰囲気だけでも残ってることに意味がある**」（masa さん）

代わりに、**小さくなりすぎた泡は描かない**（→ §「描く」）。これは規則ではなく画面の話。

値段：**合わせなかった軸に隙間が空く**。「倍率は1つの数・泡は矩形のまま」からの必然。

### 解く順番

```
resolveSpace(空間, その空間を持つ泡の画面上の配置 host):
  各軸について   値 → 位置（並べ方） → 画面（レンズ）
  ★ 合成はここ1回だけ
      画面x = host.left + ローカルx × host.scale
      scale = host.scale × ローカルscale
  中に空間を持つ泡なら、その配置で再帰
```

深さ n でも `scale` は**数値1つ**。

描く順は `q.dz − p.dz || p.scale − q.scale || 並び順`（**Z が同じなら、大きく写るものが手前**）。**View の外の状態は持たない。**
3つとも同じなら、上下は View から決まらない（＝ Z に「順序」を刺す）。

**切り抜きはしない。**

**小さくなりすぎた泡は描かない。** 遠くのものは「雰囲気」として残ればよく、読める必要はない。
いまも題名は 12px × 倍率が 6.5px を切ったら描いていない。その延長で、**泡そのものにも下限を置く**。
いくつにするかは未決。

## ② 操作は、軸と、何を掴んだかで決まる

| 掴んだもの | 軸 | 起きること |
|---|---|---|
| 泡を横・縦に引く | X / Y | その軸の次元が **書けるなら書く**／**書けないなら視点が動く**／**なしなら何も起きない** |
| 背景を引く | X / Y | 掴んでいないので、いつも視点（なし のときを除く） |
| ホイール | Z | 同上 |
| 泡を触る | Z | 書けるなら、そこへ書く（＝ **手前へ**） |
| 右下の角を引く | — | 大きさを変える |

**逆変換は軸ごと**（画面の移動量 → そのレンズの unproject → 空間の中の移動量）。
書き込む先は、**その軸に刺さっている次元**。

### 触った泡へ、視点が寄る

> **触るのは「見る」ことであって、「動かす」ことではない。**
> **だから触っても値は1つも書かない。その泡へ焦点が寄るだけ。**

②はもともと「掴んでいないなら視点」と言っている。背景を引くのも、ホイールも、その枝。
**触るのも掴んでいない**ので、同じ枝に乗る。新しい仕組みは要らない。

| その空間の軸 | 触ったとき |
|---|---|
| 焦点を送れる軸 | その泡が**その軸の焦点**になる（魚眼なら中央で原寸、ほかは端で縮む） |
| 送れない軸（箱にぴったり） | 何も起きない |

> 実測（coverflow・X＝順序·等間隔·魚眼）：端の泡を触ると
> 倍率が `0.31 0.56 0.84 0.98 0.84 0.56 0.31` → `0.03 0.07 0.16 0.31 0.56 0.84 0.98` に変わり、
> **焦点はその泡の位置（204.0）まで届く**。触った泡が中央で原寸（0.98）になる。
> **泡の値（順序・自由X）は1つも変わっていない。**

**これで「触ると Z に書く」が無くなる。** 泡の `order` を X と Z で取り合うことも無くなり、
**「横に並べる」と「触ると主役が変わる」が同時に成り立つ**（前者は X、後者は焦点）。
⑤（触っていない泡は動かない）も、値を書かないので考えるまでもなく守られる。

**重なりの上下**は、触っても変わらない。変えたいなら**掴んで引く**（＝②の「書けるなら書く」）。

## ③ 見えない親は、体を持たない

「A の左に B がスナップしている」＝「**見えない親が、中身を左右に並べている**」。

> **箱も、奥行きも、View も、自分のものは何ひとつ持たない。持っているのは並べ方ひとつだけ。**

- 箱はヘッダ 0・余白 0 で、**どの並べ方でも中身ぴったり**
- **Z は軸まるごと外の窓のもの**（次元・並べ方・レンズ・焦点のぜんぶ）
- **View を選べない。** 軸セレクタもプリセットも、外へたどった窓へ回る
- 当たるのは外周だけ。空間の出入りも、外へたどった窓で数える

---

## ④ 並べる＝帯の式

> **値ごとに帯を作り、帯の中に揃えて置き、塊の中央を空間の中心に置く。**
> **等間隔と詰めるの違いは、帯の幅の決め方だけ。**

`equal` / `pack` の軸では、空間を持つ泡の箱は**中身が収まるまで伸びる**。
`as-is` の軸では自前の大きさ。

---

## ⑤ 触っていない泡は、画面の上で動かない

> **泡の位置は、箱の中心。だから中身が変わって箱が伸び縮みしたら、**
> **触っていない泡の見えている場所を保つように、位置を書き直す。**

**誰を留めるか**（ここを1つ間違えると、入れ子の外側ごと動く）:

- 留めるのは、**空間の中身が変わったとき**だけ（泡が入った・出た・大きさが変わった）
- 同じ空間の中での**並べ替えは留めない**
- 書き先は、その泡から**外へたどって最初に「その軸が自由な空間」にいる泡**の座標
- `pack` への差し込みでは、留められるのは**差し込む所より前**だけ。後ろは差し込んだ泡の幅ちょうど動く（詰めるの意味そのもの）

**なぜ「位置＝左上」にしないか**：中心は、レンズ・消失点・魚眼の半幅・当たり判定まで一本で通っている。
そこだけ崩すと全部を直すことになる。**中心を貫き、補正を持つ**ほうを選んだ。

---

## 継承

- `view` を持つ空間はそれを使う
- 持たない空間は、**並べ方を外から継ぐ。焦点は継がない**（継ぐと窓が自分の視点を失う）
- 軸セレクタは、**選択中の泡がいる空間**に効く

## 決まったうえで残る性質（穴ではない）

- `equal` × 魚眼 は重なる。間隔より広い泡が帯からはみ出す並べ方だから
- 自由座標の Z では、同じ面に来た泡の上下が決まらない
- `pack` への差し込みでは、後ろの泡が動く
- min が合わせなかった軸には隙間が空く
