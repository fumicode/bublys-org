# 曼荼羅UI

**魚眼の海は見渡すのが得意なかわりに、「指す」のが苦手になる。** そこを埋めるための操作規則。
2026-10-13〜14 の議論と実装の記録。まだ途中なので、**決めたこと**と**引っ掛かっている所**を分けて書く。

- 実物: [`bublys-libs/mandara-ui`](../../bublys-libs/mandara-ui) ／ 台: [`apps/bublys-os/app/mandara-ui`](../../apps/bublys-os/app/mandara-ui)
- 手で触るモック（単一 HTML。テンキーで動く）: [`bublys-libs/mandara-ui/mock/index.html`](../../bublys-libs/mandara-ui/mock/index.html)

## 0. なぜ要るか

魚眼は位置を `H·tanh(u/H)` で畳むので、焦点から遠い泡ほど小さく写る（倍率 `1/cosh²`）。
これは「狭い画面を広く使う」という目的そのもので、**見渡す**方は効いている。

一方、焦点を動かす手は 3 つしかない。

| 手 | 性質 |
|---|---|
| 背景をドラッグ | 連続。「あの泡へ」と指定できない |
| ホイール（Z） | 連続。同じ |
| **泡を触る** | **離散。その泡へ焦点が寄る** |

**離散に飛べるのは「触る」だけで、それは的を狙うことを要求する。** そして魚眼では
遠い泡ほど小さい ── つまり**速く行きたい相手ほど的が小さい**。ここが逆進している。

透視（Z）が掛かっていれば、的は小さいだけでなく**手前の泡に隠れ**もするし、
焦点より手前は消える決まりなので、そもそも触れない相手もいる。

> **曼荼羅が変えるのはレンズではなく、指し方。**
> 泡ではなく**向き**を指す ── 向きの的は、泡の大きさと関わりなくいつも大きい。

## 1. 決めたこと

### 1.1 形

画面を**中央と 8 つの向き**に分ける（四正と四隅）。中央に居るのが、いま見ている泡。

```
  7 8 9        NW N NE
  4 5 6   ＝    W  ・ E      5 は「中へ」、0 は「来た所へ戻る」
  1 2 3        SW S SE
```

テンキーの並びが、そのまま向きの並びになっている。

### 1.2 仕切りは可変

- **その向きに泡がいるときだけ線を引く。** 居ない向きの帯は、中央が吸収する
- 泡が 1 つだけなら線は **0 本**（画面ぜんぶが中央）
- 端の帯は各辺の **1/6**。中央はその残り（四方が埋まれば 2/3 × 2/3）
- **同じ向きに 2 つ以上いても区画は 1 つ。** その中を分け合う

### 1.3 フォーカスが中央を決める

見る側が変われば、地図は描き直される。一覧を見ているときに詳細が東なら、
詳細を見ているときは一覧が西 ── **ただし、いつもそうとは限らない**（次項）。

### 1.4 向きは一方通行

**8 方向に何が座るかは、泡ごとに自分で持つ。** 裏返して計算しない。
だから「行けるが戻れない」が起きる。**そのための `0`**（来た所へ戻る）。

### 1.5 モードである

曼荼羅は**入り切りできるモード**。切っているあいだは今までどおりの海で、
自由移動（掴む・背景を引く・寄り引き）はそのまま生きている。

切り替えは**岸に貼ったアイコン**。小さい箱を配られた中身は印だけの姿になり、
**その印が入り切りの口**になる（ポケットと同じ「場が測って箱を配る。中身は配られた
箱で姿を決める」）。

### 1.6 切れば戻る。ただし、あいだに開いた泡は残す

入る前から居た泡だけを元の所へ戻し、曼荼羅のあいだに開いた泡はそのまま置いておく。

### 1.7 中央になれるのは、海に直に浮いている泡だけ

曼荼羅は**海**を区画に分けるもので、区画は海の座標で切ってある。
一覧の中の札のように海に居ない泡は、中央にも周りにも座らない。

## 3. できているもの

### 3.1 ライブラリ `@bublys-org/mandara-ui`

```
src/lib/domain/mandara.ts   向きの集合 → 区画と線。React も世界も知らない
src/lib/domain/place.ts     泡と向き → 画面の矩形（区画の分け合いもここ）
src/lib/ui/MandaraGrid.tsx  受け取った線を描くだけ
src/lib/feature/MandaraMode.tsx  モードの持ち方と、切り替えバブルの中身
```

テスト 15 本。区画が重ならず隙間なく画面を埋めること、居ない向きの帯を中央が
吸収すること、同じ向きに 2 つでも区画が 1 つであることを、数で固めてある。

★ **向きを決めるのは domain ではない。** 呼ぶ側が決めた向きを受け取るだけなので、
決め方（開いた関係か、実際に居る場所か）を変えても domain は動かない。

### 3.2 台 `apps/bublys-os/app/mandara-ui`

**OS の海そのもの**（`BubbleSea` ＋ OS の `bubbleRoutes` ＋ `HOMES`）の上に載せている。
岸もランチャーも見え方の口も家具も、本番と同じ。

OS 本体から借りているもの（借り漏らすと、触ったことのないブラウザでだけ壊れる）:

| 借りたもの | 無いとどうなるか |
|---|---|
| `useEnsureMainLauncherEntity()` | **ランチャー "main" は無い**と出る |
| `useEnsureBublyLaunchers()` | ロードしたバブリの呼び出しが中身を持たない |
| `useBubbleRoutes()` | あとからロードしたバブリが開けない |
| `rules={SEA_RULES}` | 両軸が魚眼のとき、4 隅の縮み方が OS と違う |

`SEA_RULES` は `BublysUINext` から公開して共有している（`HOMES` と同じ理由 ──
数を書き写すと片方だけ古くなる）。

### 3.3 共有ライブラリに足したもの

どちらも**足すだけ**で、既存の振る舞いは変えていない。

- **`bubble-layout-feature` の `moveTo(id, rect)`** ── 既にある泡を、画面のその矩形に
  見えるように動かす。中身は `takeIn` が持っていたコードを `movedTo` という純関数に
  出して分け合っている。**掴んで動かすのと同じ道**（`dragBubble`）を通るので、
  レンズの逆写しが効く
- **`bubble-space-shell` の `onSelect` / `onSettled`** ── 岸に貼った泡は海の外で
  描かれるので、`SelectedBubbleContext` に届かない。海の中に立っている `SpaceHandle`
  が受け取って外へ渡す。`onSettled` は器自身の記録と**両方**呼ぶ（横取りしない）

## 4. 踏んだこと（実測）

| 症状 | 原因 | どうしたか |
|---|---|---|
| 西の帯に置いたはずの一覧が x≈549 に出た（窓 828） | 座標を直に書いていて、背景を引いたぶんの焦点が残っていた | `moveTo` に替えた。レンズの逆写しを通るので、焦点も寄りも面倒を見てくれる |
| 東の帯で詳細が高さ 244 に潰れた（780÷3 − 余白） | 一覧の**中の札**まで「一覧が開いたもの」と数え、3 つで帯を分け合っていた | 海に直に浮いている泡だけを数える |
| 中央の矩形は {146, 8, 674, 764} と正しいのに、泡が画面の外に残った | 中央になる泡を絞っていなかった。海に居ない泡を海の座標で動かしても効かない | 中央になれるのも、海に直に浮いている泡だけにした |
| 切った瞬間、あいだに開いた泡が消えた | `restore` で世界を丸ごと戻していた | 入る前から居た泡だけ戻し、あとから来た泡は残す |
| モードに入れたあと、泡を押しても中央にならない | 選択は**変わったとき**しか知らされない。入る前から選ばれていた泡は押し直しても無反応 | 最後に触られた泡を覚えておき、入れたときに中央へ据える |
| ランチャーが「"main" は無い」と出た（新しいブラウザだけ） | 岸の定位置（`HOMES`）だけ借りて、集約を作る一行を借りていなかった | `useEnsureMainLauncherEntity()` を借りた |

## 5. いま引っ掛かっている所

### 5.1 `5`（中へ）── 規則の議論が残っている

判定そのものは `api.hasSpace(id)` ですぐできる。難しいのはその先。

曼荼羅は**海**を分けるものなので、中へ入ったら**その中の空間に曼荼羅を敷き直す**
ことになる。規則①が「入れ子ごとに繰り返される」と言っているので筋は通るが、
決めていないことが 3 つある。

- 中に入ったあと、**外の海はどう見えるか**（背後に残る／外側の区画が中の空間の縁になる）
- 中の曼荼羅の向きは何から決まるか（一覧の中の札には「開いた関係」が無い）
- 出るのは `0` か、`5` を押し直すのか

### 5.2 区画内に閉じ込める ── 置き場所が決まらない

モード中でも泡を区画の外へ動かせるし、区画より大きくできる。

やること自体は**岸がまったく同じことをしている**（`clampMoveAmongDocked` /
`clampResizeAmongDocked` / `fitAmongDocked`）。相手が「空き区間」か「区画」かの違いだけ。

★ **引っ掛かりは、挟む場所をどこにするか。** 模型（`drag.ts` / `reshape.ts`）に入れると
「区画」という概念が `bubble-layout` に漏れる。器の側で挟むほうが筋に見えるが、未決。

### 5.3 向きが東西の 2 つしかない

いまは開いた関係だけ（開いた先が東、開いた元が西）。変えるのは `membersOf()` の
1 か所だけだが、**何から向きを出すか**が決まっていない。

- **いま実際に居る場所**（中央から見た角度を 8 等分）── 自由移動と噛み合う
- **型ごとの決めごと**（一覧の右は詳細、下は地図…）── 「場所と動作が一番関連付け
  やすいものをその位置に」という元の狙いはこちら
- 両方（決めごとがあればそれ、無ければ位置）

### 5.4 魚眼・寄りが掛かっているときの大きさ

**位置**は `moveTo` なので正しく着く。でも**大きさ**は倍率 1 を前提に出している。

```
setSize(区画の大きさ − 装い)
```

魚眼が点いていたり寄っていたりすると、区画からはみ出すか、埋まらない。
いまの既定（平行・寄り 1）では正しいので目に見えていないが、穴は空いている。

### 5.5 `Maximum update depth exceeded`（未決）

岸に貼った泡を岸へ向かって縮めたときに出た。輪の形までは分かっている。

```
SpaceHandle の useEffect → onReady(api) → setSpace(api) → 描き直し → また onReady …
```

`ShoreSpace` の元からあるコードだが、**OS 本体での再現ができていない**ので、
元からあるのか曼荼羅が引き金なのか、まだ言えない。
次にやること: `api` がどの条件で作り直されるかを数え、毎回作り直されているなら
`SpaceHandle` 側で「同じなら知らせない」を入れる。

## 6. まだ決めていないこと（細かいぶん）

- **空いた向きは地が覗いて穴になる**（右下だけ暗い、など）。どう見せるか
- **斜めが埋まると帯が 2 本いっぺんに出る。** 中央が 2 方向から削られるのが意図どおりか
- **`0` の行き先。** いまは「来た道の 1 つ前」。この repo には「開いた元（親）」という
  別の意味が既に記録されている（`openAt` が書く `hist` と opener）。まっすぐ辿るうちは
  同じで、飛び回ると食い違う
- **テンキーの無い端末**（ノート・スマホ）での指し方
- モードのあいだを世界線に記録するか（いまはしていない。風・針と同じ扱い）
- **等分の 3×3 では、四隅が中心から 45° ではない。** 横長の画面ほどずれる
  （人が感じる向きと、当たる区画が食い違う可能性）
