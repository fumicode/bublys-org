# 世界線ビューア（インスペクタ）

`bublys-libs/world-line-graph` に入っている、世界線の中身を人が覗くための道具。

| | 実装 | バブル |
|---|---|---|
| 2D インスペクタ | `src/lib/feature/WorldLineInspector.tsx` | `hotel-shift-puzzle/world-line-inspector` |
| 3D インスペクタ | `src/lib/feature/WorldLine3DInspector.tsx` ＋ `src/lib/ui/world-line-3d/` | `hotel-shift-puzzle/world-line-3d` |

世界線そのものの設計は [world-line-graph-design.md](./world-line-graph-design.md)。
ここには**読み方と拡張の仕方**だけを書く。

---

## 何のための道具か

世界線は「参照（グラフ）」と「値（CAS）」が別々に生きている。参照は消えないが、値は
メモリ上の CAS から追い出されて IndexedDB にだけ残る。さらにスコープが入れ子になり、
オブジェクトごとに世界での立場が違う。**この状態は普通の画面からは一切見えない。**

だから覗く道具が要る。そして道具の第一の掟は1つだけ。

> **図は嘘をつかない。分からないものは「分からない」と描く。
> 図に出せなかったものは黙って消さず、必ず申告する。**

デバッグ道具が嘘をつくと、無いより悪い。実装のあちこちにある分岐は、ほぼこの掟が理由。

どちらのインスペクタも**読み取り専用**。覗くだけで世界が動いてはいけないので `moveTo` すらしない。

## 3D インスペクタの読み方

### 軸

| 軸 | 意味 |
|---|---|
| X | **時刻**。同時に起きたことは同じ位置に並ぶ（編集ステップ数ではない） |
| Y | **分岐**。世界線が枝分かれすると広がる |
| Z | **入れ子の段**。世界の中の世界が奥へ伸びる |

X を編集ステップ数ではなく時刻にしてあるのは、`Schedule:x` を1回操作すると、その勤務表の
世界とグローバル台帳の**両方**に世界ができるため。ステップ数で並べると、同じ操作の結果が
図の別の場所に散る。

### 板とセルと席

板1枚 ＝ 世界線のノード1つ ＝ 「その時点の世界の全体状態」。
板の上には**席**（`Slot`）が並び、1席に1オブジェクトが載る。

- 席は**世界ごと**に配る。全世界で共通にすると、5種類しか居ない勤務表の板が
  グローバル台帳の席数を背負い、板の9割が空白になってセルが数ピクセルに潰れる
- 席は型ごとに行が折り返るので **1行＝1型**。行の左の欄（型名欄）に型名を出す
- 席は同じ世界のどのノードでも同じ位置。だから同一性の線が時間軸に平行なレールになる

### 色は3つの軸を語る。混ぜない

| 軸 | どこに出るか | 値 |
|---|---|---|
| **出来事**（このノードで起きたこと） | セルの塗り | 作られた=白 / 変わった=黄 / 消された=赤 / そのまま=淡灰 |
| **値の所在** | セルの縁と明るさ | メモリ / 永続のみ / 消失 |
| **世界での立場** | 行の帯とセルの塗り | 固定メンバー=シアン |

3つとも色相に割り当てると、どれも読めなくなる。だから所在は縁と明るさに逃がしてある。

### 印

| 印 | 意味 |
|---|---|
| セルが厚みを持って手前へ出る | そのノードで出来事があった |
| 十字の墓標（赤） | **そのノードで消された**。以降のノードには描かない |
| セル同士をつなぐ線 | **同一性**。同じ `type:id` を時間方向につなぐレール |
| シアンのレール | 固定メンバー。動かないので「打ち込まれた杭」に見える |
| 行の左のシアンの帯 ＋「固定」 | その行の型が丸ごと固定メンバー |
| セル左下の三角（黄／赤） | 焼き付けた参照が**外の現在地と食い違っている**（＝固定が効いている証拠） |
| セル右上の丸 | 入れ子の世界線を持つ。**●＝開いている / ○＝畳んでいる** |
| 板から奥へ広がる半透明の面 | 入れ子の**包含**。「この ■ の中がこの世界」を語る |

**消したものを以降描かない**のは掟の帰結。もう存在しないものを描き続けたら嘘になる。

**畳んだ入れ子の印を消さない**のも同じ。印を消すと開き直す手がかりが図から無くなり、
畳む操作が片道切符になる（実際にそうなっていて、直した）。

### 入れ子の面

親セルの小さな口から、子の世界の手前の面へ、四角錐台の側面を4枚張る。断面は
**Z（入れ子が伸びる方向）を法線に持つ**。板と同じ X 法線にすると口も奥も同じ平面に乗り、
4枚が1枚に潰れて面にならない。

アドレス連動する入れ子（親を戻すと子も戻る）と、名前の規約が揃っているだけの入れ子は
**色ではなく奥側の頂点αで分ける**。連動しないものを一様に描いたら嘘になる。

## 操作

| 操作 | 効果 |
|---|---|
| ドラッグ | 回す |
| **shift + ドラッグ** | 視点の平行移動（画面の右・上に沿う） |
| ホイール | ズーム |
| shift + ホイール／横スクロール | 時間送り（**X 軸だけ**） |
| クリック | 板を選ぶ。選んだ板はセルが不透明になる |
| 入れ子を持つセルをクリック | その世界線を開く／畳む |
| 斜め / 板 / 年表 / 俯瞰 | 視点のプリセット（押すたびに図全体に合わせ直す） |

平行移動を**画面の基底**（カメラの right / up）に沿わせているのは、ワールドの X/Y に
沿わせると、板を正対で見る向きで横ドラッグが奥行き方向になり「横に動かない」が別の形で
戻るため。shift+ホイールの時間送りとは役割が割れている（時間軸に厳密に沿う／見ている面で
自由に滑る）。

板の法線は **X（時間軸）**。板の面を見るには X 軸に沿って見る（`yaw = ±90°`）ので、
`yaw = 0` の「年表」では板がエッジオンになり、時間の流れと分岐・入れ子の構造だけが見える。

## 図が申告すること（HUD）

図に出せなかったものは黙って消さず、必ず数を出す。

| 申告 | 意味 |
|---|---|
| 図に出ていないスコープ | グラフはあるが図に載っていない（IndexedDB にしか無いものなど） |
| ノードが無いスコープ / 親を辿れないノード / 親より古い時刻のノード | 壊れたグラフ |
| 要約表示 N 枚 | テクスチャの予算を超えた板。**中身が省略されている**（印も出ない） |
| 畳んで隠れている世界 N 件 ＋「全部開く」 | 自分で閉じたもの。逃げ道 |
| 削除済み N 件を墓標で表示 | 2D インスペクタの件数との差はこの分 |
| 参照だけ載って値は変わっていないもの N 件 | 強調していない |
| 固定メンバー N 口 / うち M 口は外の現在地と食い違い | 焼き付けの口数（板ごとの延べではない） |
| ⚠ 固定と申告されたのに動いたセル N 件 | **申告か仕組みのどちらかが壊れている** |

「N 口」は **(世界, オブジェクト) の組**の数。板ごとの延べにすると、9人の固定メンバーが
板の枚数ぶん数えられて「81件」になり、人数と読み違える。

## バブリからの拡張

ライブラリは特定のバブリの語彙（`Staff` / `Membership` / `APP_SCOPE_ID`）を**知らない**。
バブリ固有の規約は、`WorldLine3DInspector` の props から**純粋関数**で注入する。

```tsx
<WorldLine3DInspector
  rootScopeId={APP_SCOPE_ID}
  resolveNestedScopeId={hotelNestedScope}  // この参照はどの世界に属すか
  resolveCellRole={hotelCellRole}          // その世界でどういう立場か
  isLinked={/* 省略可 */}                  // 親とアドレス連動しているか
/>
```

| 注入 | 型 | 省略したら |
|---|---|---|
| `resolveNestedScopeId` | `(ref, currentScopeId) => string \| null` | `${type}:${id}` 規約 |
| `resolveCellRole` | `(ref, currentScopeId) => CellRole \| null` | 全セル `null`（立場を描かない） |
| `isLinked` | `(childScopeId, parentScopeId) => boolean` | 全部 `nominal`（名前の規約だけ） |

`CellRole` は `'live' | 'pinned' | 'external'`。バブリ側の所属宣言（`Membership`）と
**同じ語彙**に揃えてある。

hotel の実装は対で1ファイルに置いてある：
`hotel-shift-puzzle-libs/src/objects/worldLineViewQueries.ts`
（`hotelNestedScope` / `hotelCellRole`）。片方だけ app 層に置くと、規約を直すときに
片方を直し忘れる。

### 注入する関数は「読むだけ」にすること

ストアや CAS を読む関数を渡すと、`useMemo` の依存が毎レンダー変わってレイアウトが
作り直される。記述子だけから導けるなら module トップレベルの `const` にできる。

### `null` は「分からない」。既定値に倒さない

`resolveCellRole` を注入していないバブリで `'live'` を返すと、図が「全部この世界のもの」と
**断言**してしまう。知らないことを知っているように描くのは嘘。

絵の側も同じで、**「印が無い＝そうではない」と読ませてはならない**。印が無いのは「不明」も含む。

## 構造上の約束（破ると静かに壊れる）

| 約束 | なぜ | どう守っているか |
|---|---|---|
| `'three'` を static import してよいのは `scene.ts` だけ | Jest（jsdom）が読み込めない。バレルから漏れるとテストが全部落ちる | バレルが `scene.js` を絶対に export しない。到達経路は `WorldLine3DView.tsx` の動的 import 1本だけ |
| セルの座標の式は `layout3d.ts` の1箇所だけ | 書き写すとずれる。実際に `scene.ts` が写して、箱だけが型名欄の上に浮いていた | `view3d.test.ts` が **`scene.ts` のソースを読んで手書きの式が無いことを検査**する |
| 判定は値ではなく参照（ハッシュ）で行う | 値は CAS から追い出されるが参照は追い出されない。値で判定すると「追い出されただけ」を「無い」と誤読する | `TOMBSTONE_HASH` は `domain/StateHash.ts` の1定数 |
| 比べ先が無いときは `'unknown'` | `'same'` に倒すと「合っている」と「そもそも見ていない」が同じ絵になる | `OutsideMatch` に `'unknown'` を持たせてある |
| 画角は `DEFAULT_FOV_DEG` の1箇所 | 別々に書くと、寸法合わせ（`fitOrbit`）と平行移動（`applyPan`）の換算だけが別の画角になり、手応えが静かにずれる | `camera.ts` が持ち、`scene.ts` のカメラもそこから取る |

## 分かっている限界

- **`scene.ts` は Jest から読めない**ので、three を使う描画そのものに振る舞いのテストが無い。
  座標は「式を書き写していないこと」を見張るテストで代替している
- **板が 160 枚を超える**とテクスチャの予算を超え、超えた板は単色の要約表示になる。
  そこでは行の帯も印も出ない（枚数は HUD に出る）
- **IndexedDB にしかないスコープ**は図に出ない（件数は HUD に出る）
- 選択を変えるたびに全部の板のテクスチャを焼き直す。CAS への書き込みでもレイアウト全体を
  計算し直す
- `applyPan` は注視点を無制限に動かせる。迷子になったらプリセットのボタンで戻す
