# 旅の空間（travel-space）

旅程・地図・アクティビティの 3 つのバブリだけを載せた**独立した SPA**。
bublys OS とは別に配る（別ドメイン）ことを前提にしている。

## OS との関係

**空間の仕組みは OS と同じものを借りる。**（複製しない）

| 借りるもの | どこから |
|---|---|
| 海の器・岸・魚眼 | `@bublys-org/bubble-space-shell` |
| 泡・ルート・掴んで運ぶ・指したものを覚える所 | `@bublys-org/bubbles-ui` |
| 一覧の並べ方 | `@bublys-org/bubble-layout-feature` |
| 岸に貼る家具（世界線・見え方の口・ポケット）と定位置 | `@bublys-org/space-furniture` |
| 呼び出しを溜めるバブリ | `@bublys-org/launcher-libs` |

**載せないもの**：OS 標準の中身のバブリ（メモ・タスク・ユーザー・グループ・CSV・
変換エディタ・囲碁）、説明、他のデモへ行く口、バブリを追加。
この空間は旅の 3 つに集中する場所なので、器と家具だけを借りて中身は持ち込まない。

プラグイン（`bubly.js`）ではない。3 つのバブリは import 済みで、外から読み込む口は持たない。

## 3 つのバブリのつなぎ方（4 つの決まり）

1. **地点は地図が持つ。** 「箱根神社」のような場所は `Spot_地点` として地図バブリにだけ居る。
   アクティビティも旅程の予定も、場所は `spotId` で指すだけ。
2. **掴んで落とすと、旅程に入る。** アクティビティの札も地図のピンも `ObjectView` なので掴める。
   旅程はそれを受け取って、その日の最後の予定の後ろに継ぐ（所要時間と料金は落とした側に聞く）。
3. **指したものは、どこでも光る。** OS が持っている「最後に指したもの」
   （`FocusedObjectContext`）に地点 ID が入るだけで、地図のピン・アクティビティの札・
   旅程の行が同時に光る。バブリごとの「選択中」は作らない。
4. **地図が映している範囲が、探す範囲。** 地図で「この範囲で探す」を押したときだけ
   探す範囲が決まり、アクティビティの一覧はその中のものに絞られる。
   映している範囲を読むと、地図を少し動かしただけで一覧が入れ替わってしまう。

依存の向きは **旅程 → アクティビティ・地図**、**アクティビティ → 地図**、地図はどこにも依存しない。
旅程がその日の地点の並びを地図へ渡し、地図は渡された並びを道として繋ぐだけ（地図から旅程は引かない）。

## 動かす

```bash
npx nx dev travel-space   # http://localhost:4007
```

地図は外の地図サービスに繋がず、`map-libs` の緯度経度から SVG で描く。
