# @bublys-org/bubble-layout

`docs/bubble-space-prototype/v5-dom/lab.html`（1832 行）の**純粋な部分だけ**を切り出した domain ライブラリ。
仕様の正は `docs/bubble-space-prototype/v4/RULES.md`。React も Redux も DOM も入っていない。

---

## 1. 結論

切り出せた。ラボと**差 0**（41 場面・のべ 2300 個の泡、浮動小数の最後の桁まで一致）。
`build` / `test`（63 本）/ `lint` の3つとも通る。

**2026-09-19、規則が2つ変わった**（`v4/RULES.md` ／ `DECISIONS.md`）。ラボと同じ形で入れてある：

| | 変わったこと | ここでは |
|---|---|---|
| ② | **触った泡は「手前へ」ではなく「視点が寄る」** ── 触っても値は1つも書かない | `raise.ts` を消して `focus.ts`（`focusOn`）にした |
| ① | **端での大きさの下限 0.32** を入れ、**同じ日のうちに取り消した** | いまは `倍率 = m × min(X の像, Y の像)`。`sizeXY` / `sizeBound` / `METRICS.SIZE_FLOOR` は無い |

★ **取り消した理由**（`DECISIONS.md`「端での下限 ── 入れたが、翌日に取り消した」）:

> 「奥に行ったバブルは読めなくてもいいよ。**雰囲気だけでも残ってることに意味がある**。
> だからこれは全然 OK。ある程度小さくなったバブルは描画さえしなくていいし」（masa さん）

取り消して戻ったもの（実測）：**触った端の泡に焦点が届く**（67.07 → **204.0**・倍率 0.73 → **0.98**）／
**`pack` × 魚眼 が重ならない**（食い込み −8.3〜−16.6px → 隙間 **11.4949 / 13.4996px**）／魚眼の箱が伸びない（368.70 → **340**）。
**平行のレンズの空間は、入れたときも取り消したときも1つも変わらない**（41 個の泡で `local === m` を `Object.is`）。

★ **「小さすぎる泡は描かない」は domain に入れない。** あれは画面の話（domain は `placements()` を返すだけ）。

変えたあと、ラボと **10 場面・のべ 580 個で最大差 5.7e-14px**（ラボが stage の左上を足して返すぶんの桁落ち）。
触る（`focusOn`）は本物のマウスのクリック 8 通りで **焦点の差 0**。

## 3. ラボと同じ数字か

headless Chromium でラボを開き、`__lab.placements()` などを取って `resolveWorld` と1つずつ突き合わせた。

| 測ったもの | 場面 | 最大の差 |
|---|---|---|
| 配置 x・y・w・h・scale・local・alpha・vis・depth・描く順 | 41 場面 × 57〜59 泡 | **0**（`Object.is`） |
| 泡の値 parent・order・free・focus・cell・hist・size | 同上 | **0** |
| 空間 host・H・vp・焦点 xyz | 59 空間 | **0** |
| View を変える（プリセット2・軸5・窓へ回る2・継承2＋実ボタン3） | 14 | **0** |
| 操作を確定（本物のマウスで引いた `commitDrop`） | 10 本 | **0** |
| 触る（`focusOn`）/ resize（⑤ pin）/ ホイール / 背景ドラッグ / 泡ドラッグ | 16 本 | **0** |
| 離す先 `slotAt`（引いている間の全部の答え） | 8 本・130 回 | **0**（後述の1点を除く） |
| 印 `markLine` / `markRect` | 3 本・51 回 | **0px** |

**0 でなかったのは1つだけ。** `snap.dist` が 130 回中 **2 回だけ 1.14e-13** ちがった。
原因は式ではなく**運び方** ── ラボの `placements()` が stage の左上（y 90.5px）を足して返すので、
ページから持ち出した矩形の下の桁が落ちる。矩形を持ち出さずライブラリ自身が解いた配置で同じ 17 回を計算し直すと **17/17 完全一致**。
ラボの生の数にラボの式を当てても同じ 1.14e-13 が出る（＝ ライブラリのせいではない）。

## 6. 次（React）に入る前に決めてほしいこと

### A. ラボの「ダブルクリックで開ける」をどこで捨てるか

**調べた結果：もう捨ててある。**

| | dblclick |
|---|---|
| `bubble-lab.html`（v1） | ある |
| `bubble-lab-v2.html`（v2） | ある（1158 行 `dblclick → focusOnSelected()` ＝ 選んだ泡に寄る） |
| v3 / v4 / v5-dom | **無い** |
| このライブラリ | **無い** |

v5 で「中へ入る」は**掴んで落とす**（`dropTargetAt` → `commitDrop`）だけ。**決めること：**

1. **このまま捨てる** ── 規則②（操作は軸と掴んだもので決まる）が一番きれい。dblclick は軸と関係ない操作なので、入れると②に穴があく
2. **ui だけの寄せ（視点）として復活** ── `withFocusAxis` を呼ぶだけ。domain は触らない。②は守れる
3. **domain に「開く」を足す** ── 規則が1つ増える。**おすすめしない**

### B. 泡の中の React と、子としての泡を API でどう分けるか

規則②のため DOM は平ら（空間を持つ泡の子は DOM 上で別の場所）＝ **portal が要る**。
「中身としての React」と「子としての泡」を混ぜると後で剥がせない。**決めること：**

1. **完全に分ける** ── 泡は `id` を持つだけ。中身は `renderBubble(id) => ReactNode` を外から1つ渡す。子の泡は domain の木だけが知っていて React は知らない。**剥がせる**
2. **children で入れ子** ── `<Bubble><Bubble/></Bubble>` と書けて読みやすいが、DOM が平らでないと②が守れないので結局 portal。**木が React と domain の2箇所にできる**
3. **中身も泡** ── 「中身としての React」を捨てる。いちばん規則に素直だが、既存の memo / calculator が入らない

### C. 補間（ease / anim）を ui のどこに置くか

domain が返すのは「いまの値から出る**目標**の配置」だけ（ラボの `mode:'snap'`）。ラボの `mode:'step'/'keep'` と `lift` は移していない。**決めること：**

1. **CSS transition に任せる** ── `transform` を書き換えるだけ。実装は最小。掴んでいる泡だけ transition を切る
2. **ラボと同じ手書き `ease`** ── `requestAnimationFrame` で毎フレーム `resolveWorld` → 補間。ラボと同じ絵になる保証があるが、React の外でループを回すことになる
